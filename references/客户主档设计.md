# 客户主档设计

> **六表**：主体 / 合同 / 价格 / SKU / 期间（13 列，含贴花金额与贴花兑付方式）/ 贴花（SCD2：条码/标准/生效起止/依据/备注）。贴花表结构与价格表同构（SCD2 生效区间），字段：商品条码、商品名称、贴花标准(元/件)、生效起、生效止、依据文件、备注。三态规则：本期有动销的 SKU 必须有当期记录（显式 0 也算），缺失即阻断。

## 第一性原理

对账产出 = f（本期三份导出，主数据）。

三份导出每月都变，主数据按月**不该**变。把「不该变的东西」从每月的原始文件里剥离出来单独存放，才可能做到「一次录入、每月复用、改一处全表生效」。

由此推出四个设计约束：

1. **存字段，不存文档**。合同 PDF 留着归档即可；对账真正引用的是其中 8 个字段。让机器读 PDF 是最不可靠的一环，也是上次出错的地方（从合同里翻条款、翻收款账号）。
2. **凡是会随时间变的量，必须带时间**。价格会调，一次调价往往涉及多个 SKU，只用「当前价」会让历史期间重算错误。价格表的主键是「条码 + 生效起」。
3. **用不会漂的键做主键**。品名会漂（括号全半角、空格、加后缀），条码不会。条码做主键，品名只作展示与别名反查。
4. **路径可推导，不要靠记忆**。主档放客户根目录，命名固定为 `_主档.xlsx`，脚本按「月份目录的上一级」自动找，不需要每次告知。

## 五张表

### 一、`主体`（谁）

| 字段 | 说明 | 示例 |
|---|---|---|
| 角色 | 甲方/乙方 | 甲方 |
| 名称 | 营业执照全称 | 示例品牌方有限公司 |
| 统一社会信用代码 | 印在对账单上 | 91440100DEMO00001A |
| 地址 | 合同通讯地址 | 示例市示例区… |
| 联系人 / 电话 | 对账联系人 | 张示例 / — |
| 开户行 / 账号 / 户名 | 仅甲方填 | 示例银行… / 假账号… |

甲方信息全客户通用，可另存全局主档后复制；乙方一行。

### 二、`合同`（按什么规则）

| 字段 | 说明 |
|---|---|
| 合同编号 | 对账单引用 |
| 起始 / 终止 | 判断本期是否在合同期内 |
| 结算方式 | 铺货代销／买断 |
| 结算基数 | 实际动销／发货／签收 |
| 账期（付款日） | 次月 5 日前 |
| 异议期（日） | 3 个工作日 |
| 签回期（日） | 5 个工作日 |
| 价格附件编号 | 指向价格表版本 |
| 备注 | 特殊约定（如额度、动销保障比例） |

**只填会被单据引用的字段。** 不要试图把整份合同结构化——投入产出不成比例。

### 三、`价格`（多少钱，带时间）

| 字段 | 说明 |
|---|---|
| 商品条码 | 主键之一 |
| 商品名称 | 展示用 |
| 供货价 | 结算单价 |
| 生效起 | **必填**，YYYY-MM-DD |
| 生效止 | 空=至今；调价时填新行并给旧行补止日 |
| 零售价 | 校验用 |
| 依据文件 | 政策表文件名+版本 |

同一 SKU 允许多行，取「生效起 ≤ 对账截止日 ≤ 生效止」的那一行。

这是整套主档里**唯一必须严格按时间维护**的表。调价当月，两行并存是正常状态，不是重复数据。

### 四、`SKU`（是什么）

| 字段 | 说明 |
|---|---|
| 商品条码 | 主键 |
| 标准品名 | 甲方口径 |
| 乙方品名别名 | 多个用 `\|` 分隔，用于反查 |
| 规格 | 内容量×片数，如 100ml、盒装5片 |
| 单位 | 盒/瓶/套/片 |
| 箱规 | 24盒/箱，用于换算 |
| 结算属性 | 结算类／非结算类（陈列、试用） |
| 备注 | 停售、替换关系 |

「乙方品名别名」这一列解决的是上次最耗时的问题：同一 SKU 在两侧系统的写法不同。填一次，之后按条码匹配即可。

### 五、`期间`（历史结果）

| 字段 | 说明 |
|---|---|
| 期间 | 202610 |
| 数据基准日 | 2026-11-02 |
| 期初数量 / 期初金额 | 用于下期衔接 |
| 本期结算数量 / 金额 | |
| 差异数量 / 金额 | |
| 对账单编号 | |
| 状态 | 待确认／已签回／已收款 |
| 备注 | 差异处理结论 |

脚本每次跑完自动追加一行。它的作用不是记账，而是**下期期初的来源**与**次年审计的索引**。

## 每期真正需要问用户的信息

主档建好之后，每次对账只剩 5 个问题：

1. 对账期间与数据基准日？
2. 三份文件在哪（默认按目录规则找）？
3. 本期有无补货、退货、调拨、赠品需要单独列示？
4. 上期是否有未确认差异需要结转？
5. 本期是否发生调价 / 新增 SKU？

前两项可由路径与文件名推断；3–5 项若无变更，默认「无」。

## 维护成本

- **建库**：一次性约 30 分钟（SKU、价格行、合同、主体，按实际规模）。
- **日常**：价格按月不调则不动；调价加一行；新 SKU 加一行；合同续签改一行。
- **月度**：主档只读不写，脚本自动回写 `期间` 一行。

净效果：把「每月重新翻合同、重新找税号、重新核价格」的一次性劳动，压缩成「变更时才动」。

## 常见错误

1. 价格表只存当前价、不存历史 → 追溯重算时全部错。
2. 用商品名称做匹配 → 遇到括号/空格差异就断。
3. 把陈列装当结算品 → 差异表凭空多出几百件。
4. 期间台账不记基准日 → 半年后无法判断当时用的是哪版价格。
