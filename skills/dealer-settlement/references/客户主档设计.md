# 客户主档设计

> **六表**：主体 / 合同 / 价格 / SKU / 期间（13 列，含贴花金额与贴花兑付方式）/ 贴花。本文件是字段级设计说明，SKILL.md 只在需要细节时引用它。

## 第一性原理

对账产出 = f（本期三份导出，主数据）。

三份导出每月都变，主数据按月**不该**变。把「不该变的东西」从每月的原始文件里剥离出来单独存放，才可能做到「一次录入、每月复用、改一处全表生效」。

由此推出四个设计约束：

1. **存字段，不存文档**。合同 PDF 留着归档即可；对账真正引用的是其中一小组字段（编号、起止、结算方式 / 基数、付款日、异议期、签回期）。让机器读 PDF 是最不可靠的一环（每次都要从合同里翻条款、翻收款账号）。
2. **凡是会随时间变的量，必须带时间**。价格会调，一次调价往往涉及多个 SKU；只用「当前价」会让历史期间重算错误。价格表的主键是「条码 + 生效起」；贴花表同构。
3. **用不会漂的键做主键**。品名会漂（括号全半角、空格、加后缀），条码不会。条码做主键，品名只作展示与别名反查。
4. **路径可推导，不要靠记忆**。主档放客户根目录，命名固定为 `_主档.xlsx`，脚本按「月份目录的上一级」自动找，不需要每次告知。

## 运行时依赖 vs 人工维护

引擎并不读取全部字段，下表说明哪些字段缺失会真正阻断，避免「文档说必填、实际没用上」的误解：

| 表 | 硬性依赖（缺失即中止） | 进入输出文案（缺失降级，不中止） | 只做核对 / 摘要 / 不读写 |
|---|---|---|---|
| 主体 | 甲乙方名称、税号；甲方开户行 + 账号 | — | 地址、联系人、电话 |
| 合同 | 合同编号 | 结算方式、结算基数（→ 对账口径）；异议期、签回期（→ 双方确认时限）；付款日（→ 付款期限，并决定 `--pay` 缺省日） | 起始、终止、价格附件 |
| 价格 | — | — | 全部字段：引擎会读该表，但只用于「挂账单单价 vs 主档」交叉校验告警；结算单价取挂账表 |
| SKU | 商品条码、标准品名、结算属性 | — | 别名、规格、单位、箱规、备注 |
| 期间 | — | — | 全部（脚本不读写；每期对账后由助手 / 人工追加一行） |
| 贴花 | 商品条码、贴花标准、生效起止（表存在时） | — | 商品名称、依据文件、备注 |

主档表名 / 列名 / 顺序发生漂移时，走 SKILL.md **阶段 0**（`inspect_schema` → 用户逐项确认 → `apply_mapping --fix-master`）修复，不要手工乱改；`_数据映射.json` 只描述对应关系，不等于数据正确性背书。

## 六张表

### 一、`主体`（谁）

| 字段 | 说明 | 示例 |
|---|---|---|
| 角色 | 甲方/乙方 | 甲方 |
| 名称 | 营业执照全称 | 示例品牌方有限公司 |
| 统一社会信用代码 | 印在对账单上 | 91440100DEMO00001A |
| 地址 | 合同通讯地址 | 示例市示例区… |
| 联系人 / 电话 | 对账联系人 | 张示例 / — |
| 开户行 / 账号 / 户名 | 仅甲方填 | 示例银行… / 假账号… |

甲方信息全客户通用，可另存全局主档后复制；乙方一行。

### 二、`合同`（按什么规则）

| 字段 | 说明 |
|---|---|
| 合同编号 | 对账单引用 |
| 起始 / 终止 | 判断本期是否在合同期内 |
| 结算方式 | 铺货代销／买断 |
| 结算基数 | 实际动销／发货／签收 |
| 账期（付款日） | 如「次月 5 日前」；其中的日决定 `--pay` 缺省日，缺失按 5 日 |
| 异议期(工作日) | 正整数，进入对账单「异议期限」；缺失写「合同约定的异议期限」 |
| 签回期(工作日) | 正整数，进入对账单「签回期限」；缺失写「合同约定的签回期限」 |
| 价格附件 | 指向价格表版本 |
| 备注 | 特殊约定（如额度、动销保障比例） |

**只填会被单据引用的字段。** 不要试图把整份合同结构化——投入产出不成比例。对账时引擎直接读本表：结算方式、结算基数进入 `00-对账说明` 与 `01-对账单` 的结算口径；异议期、签回期进入双方确认时限；付款日进入付款期限，并作为 `--pay` 的缺省日。缺项不会印演示值：结算方式 / 基数缺失写「（主档未登记，以合同为准）」，异议期 / 签回期缺失写「合同约定的异议期限 / 签回期限」，付款日缺失按次月 5 日。起始、终止、价格附件只用于摘要与人工核对（对账期间由 `--period` 决定）。

### 三、`价格`（多少钱，带时间）

| 字段 | 说明 |
|---|---|
| 商品条码 | 主键之一 |
| 商品名称 | 展示用 |
| 供货价 | 结算单价（当前结算实际取甲方挂账表单价，主档价用于交叉核对） |
| 生效起 | **必填**，YYYY-MM-DD |
| 生效止 | 空=至今；调价时填新行并给旧行补止日 |
| 零售价 | 校验用 |
| 依据文件 | 政策表文件名+版本 |

同一 SKU 允许多行，取「生效起 ≤ 对账截止日 ≤ 生效止」的那一行。

价格与贴花是整套主档里**必须严格按时间维护**的两张表。调价当月，两行并存是正常状态，不是重复数据。

### 四、`SKU`（是什么）

| 字段 | 说明 |
|---|---|
| 商品条码 | 主键 |
| 标准品名 | 甲方口径 |
| 乙方品名别名 | 多个用竖线分隔，用于反查 |
| 规格 | 内容量×片数，如 100ml、盒装5片 |
| 单位 | 盒/瓶/套/片 |
| 箱规 | 24盒/箱，用于换算 |
| 结算属性 | 结算类／非结算类（陈列、试用） |
| 备注 | 停售、替换关系 |

「乙方品名别名」这一列解决的是最耗时的问题：同一 SKU 在两侧系统的写法不同。填一次，之后按条码匹配即可。

### 五、`期间`（历史结果）

| 字段 | 说明 |
|---|---|
| 期间 | 202610 |
| 数据基准日 | 2026-11-02 |
| 期初数量 / 期初金额 | 用于下期衔接 |
| 结算数量 / 金额 | |
| 差异数量 / 金额 | |
| 贴花金额 / 贴花兑付方式 | 抵扣货款／分开支付／待定 |
| 对账单编号 | |
| 状态 | 待确认／已确认／已对账／已付款／已签回／已收款 |
| 备注 | 差异处理结论 |

共 13 列。**脚本不读写这张表**：引擎只读主档的「SKU」「价格」「贴花」，写完对账单后由助手或人工追加一行。它的作用不是记账，而是**下期期初的来源**与**次年审计的索引**；漏登记即断链。

### 六、`贴花`（销售奖励标准，带时间）

| 字段 | 说明 |
|---|---|
| 商品条码 | 主键之一 |
| 商品名称 | 展示用 |
| 贴花标准(元/件) | 本期结算类动销每件奖励金额；无奖励也要显式登记 0 |
| 生效起 | **必填**，YYYY-MM-DD |
| 生效止 | 空=至今；调标时旧行补止日、新行填生效起 |
| 依据文件 | 政策表文件名+版本 |
| 备注 | 源表问题、确认记录 |

结构与价格表同构（SCD2）。**三态规则**：

- 主档无「贴花」表 → 跳过贴花模块并提示（不阻断对账）；
- 有表 → 本期有动销的每个 SKU 必须有当期有效记录（显式 0 也算），缺失即阻断；
- 同一时点同一条码命中多条生效记录（区间重叠）→ 阻断，不按行序猜。

**兑付方式不写在贴花表里**，而是在对账单口径说明中列示、由双方书面确认后登记到「期间」表的「贴花兑付方式」列。

## 每期真正需要问用户的信息

主档建好之后，每次对账只剩 5 个问题：

1. 对账期间与数据基准日？
2. 本期有无补货、退货、调拨、赠品等非动销变动需要单独列示？
3. 上期是否有未确认差异需要结转？
4. 本期是否发生调价 / 调贴花（旧行补止日、新行起新生效日）？
5. 本期是否新增 SKU / 门店，主档与贴花表是否已登记？

第 1 项可由 `--period` / `--asof` 明确；2–5 项若无变更，默认「无」。

## 维护成本

- **建库**：一次性，通常半小时量级；SKU、价格行、主体越多越久。
- **日常**：价格按月不调则不动；调价加一行；新 SKU 加一行；合同续签改一行；贴花按政策表加行。
- **月度**：主档只读；对账结束后追加「期间」一行（脚本不自动写主档）。

净效果：把「每月重新翻合同、重新找税号、重新核价格」的一次性劳动，压缩成「变更时才动」。

## 常见错误

1. 价格表只存当前价、不存历史 → 追溯重算时全部错。
2. 用商品名称做匹配 → 遇到括号 / 空格差异就断。
3. 把陈列装当结算品 → 差异表凭空多出几百件。
4. 期间台账不记基准日 → 半年后无法判断当时用的是哪版价格。
5. 贴花表调标时覆盖旧行 → 往期贴花不可复现；正确做法是两行并存。
6. 本期有动销的 SKU 在贴花表漏登记 → 引擎直接阻断；没奖励也要登记 0。
7. 合同表只登记编号、不登记结算方式 / 异议期 / 签回期 / 付款日 → 对账单印「主档未登记，以合同为准」占位；出正式单据前先补齐主档。
