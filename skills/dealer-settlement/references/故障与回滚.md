# 故障与回滚

本文件是 SKILL.md 第 10 节的完整版：输出约定、`RECON_CFG` 结构、报错对照（含 L6 复核、阶段 0 映射与确认单定位）、回滚步骤。按需查阅，不必预读。

## 输出与退出约定

| 脚本 | stdout | stderr | 退出码 |
|---|---|---|---|
| `load_master.py` | 单行 `RECON_CFG` JSON（供 `export` 捕获） | `[主档告警]` / `[提示]` / 参数、主档、目录错误 | 出错 → 非 0 |
| `recon_engine.py` | 成功时 `[新建] <绝对路径>`、`[覆盖→<新文件名>] <绝对路径>`（目标已存在、自动写 `_v2`）、`[覆盖] <绝对路径>`（显式 `overwrite: true`）、`SAVED: <路径>`、`大小 N KB`；**失败时 stdout 保持 0 字节** | 过程日志、`⚠` 告警、`[自检未通过]` 详情、`[中止]` / `[保护]` / `[写入失败]` / `[缺少依赖]` | 失败 → 1 |
| `apply_contract.py` | 差异表（新增 / 冲突 / 跳过 / 拒绝）、合计行、归档与备份提示 | 错误文案（`sys.exit`） | 冲突且未加 `--force` → 1；主档不可读 / 写入失败 → 非 0 |
| `extract_contract.py` / `make_digest.py` | JSON / Markdown 正文 | `[提示]`、`[很可能不是文本版]` 等 | 文件或格式问题 → 非 0 |
| `make_confirm_html.py` | 生成路径、分组统计（提交后确认单由 `locate_confirm.py` 自动定位；浏览器支持时可直接存入客户目录） | —（错误文案走 `sys.exit`） | 参数 / JSON 错误 → 非 0 |
| `locate_confirm.py` | 最新确认单绝对路径（或候选列表） | `[未找到确认单]` / `[确认单有多个候选]` 等中文原因 | 0 = 已定位；2 = 多份候选；1 = 未找到 |
| `make_review_packet.py` | 复核包 JSON / MD 与摘要 | 取数缺失 `warnings`、失败中文原因 | 失败 → 1 |
| `apply_review.py` | 默认 dry-run 校验摘要；`--apply` 落盘与归档摘要；`--check` 通过打印「复核有效」 | 各中文原因（哈希不一致 / checklist 缺项 / 结论不一致 / 锁失效等） | 不通过或校验失败 → 1；通过 → 0 |
| `inspect_schema.py` | 探查 JSON / MD | 文件不可读原因 | 发现漂移仍 0；文件不可读 → 1 |
| `apply_mapping.py` | dry-run 计划 / 写入与归档摘要 | 未确认、映射指向不存在、写入失败 | 失败 → 非 0 |

引擎只在**保存成功之后**才写 stdout；参数、源数据、自检任一失败时 stdout 保持 0 字节（CI 会断言）。写盘走 `*.tmp.xlsx` → `os.replace`，失败会清掉临时文件，不会留下半成品。

## RECON_CFG 结构（load_master.py 生成）

用户无需手填：`export RECON_CFG=$(python3 "$SKILL_DIR/scripts/load_master.py" <主档> --period 202610 --asof 2026-11-02)` 即可。以下字段供排错与高级开关使用：

| 字段 | 必需 | 说明 |
|---|---|---|
| `party_a` / `party_b` | 是 | `name`、`tax` 须非空；`addr` / `contact` / `phone` 仅展示 |
| `contract` | 部分 | `no` 必需；`start` / `end` / `method` / `basis` / `pay_day_text` / `objection_days` / `signback_days` / `price_annex` 可缺——缺项在对账单写「主档未登记，以合同为准」/「合同约定的…」占位 |
| `period` | 是 | `start` / `end` / `asof`（YYYY-MM-DD）；`period_cn` / `asof_cn` / `pay_cn` / `next_month` / `out_name` 缺失时自动推导 |
| `bank` | 是 | `account_no` + `bank_name` 非空；`account_name` 缺省取甲方名称 |
| `base_dir` | 是 | 月份目录（load_master 自动定位，绝对路径） |
| `sources` | 是 | `jia` / `sales` / `inventory` 三个文件名 |
| `master_path` | 是 | 主档绝对路径（load_master 自动生成；引擎读 SKU / 价格 / 贴花用） |
| `out_file` | 否 | 输出文件路径（来自 `--out`，load_master 转绝对路径） |
| `overwrite` | 否 | `true` 时覆盖同名输出；缺省写 `_v2` |
| `allow_large_diff` | 否 | `true` 时跳过「差异率 > 30%」中止（谨慎使用） |
| `verify_notes` | 否 | `[[标签, 文本], …]` 自定义 `03-源数据对照` 的「源数据核对记录」 |
| `mapping` | 否 | 客户根目录存在 `_数据映射.json` 时由 load_master 自动注入；引擎按其选表 / 表头行 / 列（结构见同目录 `数据映射与结构探查.md`） |

排错提示：设置环境变量 `RECON_DEBUG=1` 后，引擎在缺配置时会额外打印缺失键清单。

## 报错对照

### 入口 / 源文件（L1）

| 报错（stderr） | 含义 | 处理 |
|---|---|---|
| `[中止] 本次对账缺少必要信息：…，未生成任何文件。` | 没先跑 `load_master.py`，或主档字段 / 源文件 / `master_path` 缺失 | 按报错给出的整行命令修复后重跑；**不要**试图绕过 |
| `[中止] RECON_CFG 不是合法的配置 JSON：…，未生成任何文件。` | 配置被截断、手改坏，或顶层不是对象 | 重跑 `load_master.py` 生成整行配置 |
| `[找不到主档] …` | 主档路径不存在 | 核对路径，或先用 `make_master.py` 生成模板 |
| `[无法读取主档] …` | 主档损坏或不是 .xlsx | .xls 先另存为 .xlsx；修复文件后重试 |
| `[参数错误] --period 需为 6 位年月…` / `--period 的月份不合法` / `--period 的年份不合法（应为 1900–2999）` | 期间格式错 | 改成 `202610` 形式 |
| `[参数错误] --asof 需为 YYYY-MM-DD…` / `[参数错误] --pay 需为 YYYY-MM-DD…` | 日期格式错 | 改成 `2026-11-02` / `2026-11-05` 形式 |
| `[缺少源文件] <路径>` +「目录 … 下现有 Excel：…」 | 文件名不含关键词，或放错期间目录 | 按 SKILL.md 1.2 命名约定改名或移动，或 `--base` 指定目录 |
| `[目录不存在] <路径>` | `--base` 或月份目录不存在 | 创建月份目录或修正 `--base` |
| `[中止] 客户根目录下有挂账文件，但没有可识别的月份子目录（如 202611/）。` | 旧导出混在客户根目录 | 放进对应月份目录，或 `--base` 明确指定 |
| `[主档告警] …` + `[提示] 共 N 项主档信息不全，仍继续生成` | 主档字段不全但非致命 | 补主档；加 `--strict` 时会直接中止 |
| `[中止] 主档关键信息不全，已按 --strict 退出。请先补全主档。` | 加了 `--strict` 且预检不通过 | 按告警补主档后重跑 |
| `[中止] 未找到含 … 的工作表…实际工作表：…` | 源文件表名无法按关键词识别 | 核对源文件是否放错 / 换版；在 `RECON_CFG` 的 `sources` 中指定文件 |
| `[中止] 含关键词 […] 的工作表有 N 张：[…]，无法确定用哪一张。` | 多张表名都匹配，脚本拒绝猜测 | 只保留一张或改表名；确需自动兜底时会以 ⚠ 提示「使用唯一含数据表」 |
| `[缺少依赖] 读取 .xls 需要 xlrd（python3 -m pip install xlrd）…` | 未安装 `xlrd` | 安装依赖后重跑 |
| `[中止] 不支持的源文件格式：…（仅支持 .xls / .xlsx / .xlsm）` | 源文件扩展名异常 | 另存为受支持的格式 |

### 计算自检（L3）与结构守卫（L4）

| 报错（stderr） | 含义 | 处理 |
|---|---|---|
| `[自检未通过] 数据表未找到含「…」的列（…）。实际表头：…` | 列名关键词不匹配 | 核对表头（乙方换 ERP 后须先更新列映射） |
| `[自检未通过] 销售工作表是「X」，但本次期间是 Y 月，疑似期间与源文件不匹配。` | 源文件与 `--period` 不符 | 换成对应月份的导出 |
| `[自检未通过] 销售流水第 N 行缺少商品条码。销售流水必须带条码…` | 销售流水有行缺条码 | 补齐条码或修正导出（不接受按品名猜算） |
| `[自检未通过] <上下文> 是布尔值（…），疑似表头/说明行混入数据区` / `… 的值「…」不是数字。缺失即阻断` / `… 不是有限数字` | 源表脏值 | 清理源表；引擎不做静默转换 |
| `[自检未通过] 明细合计 A ≠ 按条码汇总 B（源表可能有合计行或空行）` | 销售流水明细与汇总不一致 | 检查源表是否有合计行 / 空行 |
| `[自检未通过] 挂账源表数量合计 A ≠ 归一化后 B（同品名多行合并异常）` | 挂账表同品名多行合并异常 | 核对挂账表品名、条码 |
| `[自检未通过] 结转残差 R，期初合计 A ≠ B` | 金额结转对不上 | 按 stderr「已算出」六个数定位 |
| `[自检未通过] 期末账面货值 ≠ 理论结存货值：A ≠ B` / `期末账面货值 － 调整后结存货值 ＋ 差异金额 ≠ 0：…` / `调整后结存货值 ≠ 库存货值 ＋ 回加货值：…` | 金额勾稽不成立 | 逐个恒等式排查（金额侧） |
| `[自检未通过] 数量恒等式不成立：期初 A ≠ 动销 B ＋ 理论结存 C`（另有「调整后结存 ≠ 库存 ＋ 回加」「差异 ≠ 调整后结存 － 理论结存」两条） | 数量恒等式不成立 | 逐个恒等式排查（数量侧） |
| `[自检未通过] 差异 N 件，占理论结存 P%，超过 30% 阈值…` | 差异异常大 | 优先怀疑源文件放错期间 / 表结构变化（确需放行可在 `RECON_CFG` 加 `allow_large_diff: true`） |
| `[自检未通过] 乙方库存表解析结果为 0 件，疑似表名或列位不匹配` | 库存表结构异常 | 核对库存文件与表头 |
| `[自检未通过] 库存文件中存在含 N 件数量记录的「次月销售」类工作表…请把 --asof 改为真实库存导出日` | `--asof` 与库存导出日不符 | 改为真实库存导出日 |
| `[自检未通过] 有 N 个商品在主档中未明确「结算类/非结算类」…` | SKU 表结算属性为空 / 未知 / 未建档 | 补主档 SKU 表后重跑 |
| `[自检未通过] 挂账表中同一条码出现多行（…），请先在主档/挂账表核对…` | 同条码多笔挂账 → 会双算动销 | 先在主档 / 挂账表核对合并，不要绕过 |
| `[自检未通过] 贴花表缺少 N 个本期动销 SKU 的有效记录…` | 贴花表缺当期记录 | 补主档「贴花」表；无奖励也要显式登记 0 |
| `[自检未通过] 贴花表有 N 个条码…命中多条生效记录（区间重叠）` | SCD2 区间重叠 | 修生效起止，保证同一时点每条码仅一条 |
| `[自检未通过] 贴花表条码 … 的「贴花标准」不是数字 / 为负数` | 主档贴花表脏值 | 修正主档；不会默认为 0 |
| `[自检未通过] 贴花合计复算不一致：A ≠ B` | 内部自检失败 | 不要交付，先核对主档贴花表 |
| `⚠ 挂账表中「…」出现多行，已按数量合计` / `⚠ 库存表内「…」出现多行，已按数量合计` | 源表拆行（告警，非阻断） | 核对自动合计是否正确 |
| `⚠ 库存表内条码 … 对应多个品名（… / …），已按条码合并` | 同条码多品名 | 核对是否同一 SKU |
| `⚠ 回加工作表「…」与推算区间 N 月不一致，请核对库存导出日` | `--asof` 可能填错 | 改为真实库存导出日 |
| `⚠ 次月销售表有 N 行无条码且品名无法匹配库存，已跳过…` | 回加表有脏行 | 核对是否影响回加数量 |
| `⚠ 销售流水有 N 行销售时间无法解析，数据覆盖期间将不含这些行` | 时间列格式异常 | 修正时间列或在披露中说明 |
| `⚠ 挂账单单价与主档价格表不一致（本期口径以挂账单为准，请人工确认）` | 挂账价 ≠ 主档价 | 与系统维护方核对；不要只改主档 |
| `⚠ 挂账覆盖条码 N 个，主档结算类 M 个，差额 […]，请确认是否漏挂/多挂` | 挂账与主档结算类 SKU 集合不一致 | 核对建档 / 挂账是否漏项 |
| `⚠ 以下 N 个 SKU 乙方本期未提供库存数据，不参与差异计算（非按 0 计）` | 库存表缺该 SKU（不按 0 计，差异无法计算） | 请乙方补报库存后重算；本期 02 表会单列「乙方未提供库存的 SKU」章节 |
| `⚠ 库存有 N 行、M 件在主档 SKU 中查不到条码，已归入非结算桶` | 主档未建档 | 建档或确认归属 |
| `⚠ N 个单品未在主档登记单位，对账单按「—」显示` | SKU 表缺单位 | 补主档单位列 |
| `⚠ 未找到含 … 的工作表，使用唯一含数据表「…」` | 关键词没命中但仅有一张数据表 | 核对是否用对了源文件 |
| `贴花：主档无「贴花」表，本期不计算销售奖励（如需计算请先建表）` | 整表不存在（非报错，跳过模块） | 如需贴花，按 SKILL.md 第 5 节建表 |

### 合同抽取 / 确认页 / 写库（L2）

**确认单定位（A3.5）**：优先用 `locate_confirm.py` 自动定位；**不得要求用户移动 / 复制 / 重命名确认单文件，也不得向普通用户解释文件格式**。

| 报错 | 含义 | 处理 |
|---|---|---|
| `[找不到合同文件] …` | 合同路径错 | 核对路径（支持 .docx/.pdf/.xlsx/.xlsm/.txt/.md） |
| `[无法读取] … 不是有效的 .docx…` | docx 缺失 `word/document.xml` 或损坏 | 用 Word 另存为 .docx 后重试 |
| `[编码无法识别] …` | txt/md 既不是 UTF-8 也不是 GB18030 | 转码后重试 |
| `不支持的格式 .doc；.doc/.wps 请先另存为 .docx` | 合同格式不支持 | 另存为受支持格式 |
| `[很可能不是文本版] 仅解析到 N 行 / M 字…` | 扫描件 / 图片型 PDF 无文本层 | 换电子版、OCR，或按确认页手工录 |
| `[提示] 仅解析到 N 行 / M 字，内容可能不完整…` | 非 PDF/docx 源文本过短 | 核对文本格式，优先提供 .docx/.xlsx 原件 |
| `[提示] N/M 个字段未识别，可能合同模板差异较大…` | 抽取率低 | 人工核对后手工补录 |
| `[JSON 解析失败] … 第 X 行第 Y 列：…` | 候选 JSON 或确认单被截断 / 改坏 | 重新抽取；若为确认单损坏，请用户在确认页重新提交，再跑 A3.5 自动定位最新确认单 |
| `[未找到确认单]` | 用户还没点「提交」、下载位置未知，或换了浏览器 / 电脑 | 一句话问用户（是否已点「提交」？是否换了浏览器 / 电脑？）；必要时 `--dir "<下载目录>"` 兜底，**不要让用户搬文件** |
| `[确认单有多个候选]` | 近期下载目录 / 客户目录有多份确认单 | 助手用最新一份并明确说「用了最新提交的那份」，或一句话请用户确认 |
| `[格式错误] … 候选 JSON 顶层必须是对象（含 fields 数组）` | 候选 JSON 结构不对 | 用 `extract_contract.py` 重新生成 |
| `[找不到文件] …` | 候选 JSON 路径错 | 核对路径 |
| `[中止] 确认单缺少确认人（meta.operator 为空）` | 确认页未填确认人 | 请用户在确认页填写姓名后重新提交，再跑 A3.5 自动定位 |
| `拒绝 …须为半角数字…` / `…日期须为 YYYY-MM-DD…` / `…仅允许：…` / `…须为 8–14 位数字条码…` | L2 脏值（全角 / 文本 / 枚举越界 / 条码位数） | 请用户在确认页修正后重新提交，再跑 A3.5 自动定位最新确认单；该项不写入，其余字段照常 |
| `[提示] N 项被类型校验拒绝，本次仅写入其余 M 项。` | L2 部分拒绝 | 按逐条原因修正后重跑 |
| `主体字段 target 需形如 主体.甲方.名称（角色.列名）` | 确认单 target 结构不对 | 请用户重新提交确认页，再跑 A3.5 自动定位（或修正候选 JSON 后重跑 A3） |
| `存在冲突且未加 --force，已中止写入。` | 主档现值 ≠ 候选值（非确认单模式） | 人工裁决；确认后用确认单或加 `--force` |
| `[无变化] 主档已是目标状态，未写盘、未备份。` | 幂等结果 | 正常，无需处理 |

### 输出 / 写入（L5）

| 报错（stderr） | 含义 | 处理 |
|---|---|---|
| `[保护] 目标文件已存在，本次写入 <名称>_v2.xlsx` + stdout `[覆盖→<名称>_v2.xlsx] <路径>` | 防覆盖，属正常保护（标记不再误报 `[新建]`） | 确认后改名，或在 `RECON_CFG` 加 `"overwrite": true`（此时 stdout 为 `[覆盖] <路径>`） |
| `[写入失败] <路径>` +「文件可能正被 Excel 打开，请关闭后重试。」 | 目标文件被占用 | 关闭 Excel / WPS 后重跑；`apply_contract.py` 会在文案中附「本次改动前的备份：_备份/…」 |
| `[写入失败] <路径>` +「磁盘空间不足或路径不可写，原文件未受影响。」 | 磁盘 / 权限问题 | 换输出位置或清理空间；原文件未被破坏（`apply_contract.py` 同样附备份位置） |

### 复核（L6）

| 报错 / 现象 | 含义 | 处理 |
|---|---|---|
| `--check` 报「复核无效」 | 工作簿复核后又被保存（哈希变化），或未做 L6 | 不得交付；重新生成复核包 → 重做 R1–R10 → `--apply` → 再 `--check` |
| 复核锁缺失 / 08 表缺失 | 从未 `--apply`，或工作簿被替换 | 重做复核并落盘，不要手工造锁 |
| `workbook_sha256` 与当前工作簿不一致 | 报告基于旧版本工作簿 | 重新生成复核包，用新哈希重写报告 |
| checklist 未覆盖 R1–R10（缺项 / 未知 id） | 报告不完整 | 逐项补齐（未知 id 只警告，仍建议核对） |
| 有 `阻断` finding 但 verdict 不是「不通过」 | 结论与证据矛盾 | 修正 verdict；不得把阻断项降级为警告 |
| 无阻断但有 `警告` 却判「通过」 | 判定违规 | 改为「有条件通过」并在 summary 写明条件 |
| `不通过` / `有条件通过` 的 summary 为空 | 缺结论说明 | 补 summary 后重试 |
| `--apply` 返回 1 且未写 08 表（verdict=不通过） | 正常阻断行为 | 先修数据并重新出账，再重评；不得绕过 |

### 结构映射（阶段 0）

| 报错 / 现象 | 含义 | 处理 |
|---|---|---|
| `必须经用户确认`（`apply_mapping.py` 缺 `--confirmed-by`） | 违反确认门禁 | 先 dry-run 展示差异，用户逐项裁决，再加 `--confirmed-by "<姓名>" --write` |
| 映射指向不存在的表 / 列（dry-run exit 1） | 映射与当前文件不一致 | 重新 `inspect_schema`，修正映射或换文件 |
| `_数据映射.json` 损坏 / 校验失败（load_master 中文报错 exit 1） | 映射 JSON 被手工改坏 | 用 `inspect_schema` 重新生成；或删除该文件回退到无映射行为 |
| 引擎报映射项不存在 | 映射与当次源文件版本不匹配 | 重新探查并确认映射；探查报告的 sha256 仅作留痕，apply_mapping 不强制比对 |
| `inspect_schema.py` exit 1 | 文件不可读（损坏 / 权限 / 格式） | 核对路径与文件类型；探查发现问题**不会** exit 1 |
| 主档修复后读取失败 | 修复计划与实际表结构不符 | 从 `_备份/` 取毫秒时间戳副本回滚，重新确认映射 |

## 回滚

| 对象 | 怎么回滚 |
|---|---|
| 主档 `_主档.xlsx` | `_备份/` 下每次写库前都有**毫秒时间戳**副本（`YYYYmmdd_HHMMSS_mmm`），取上一版复制覆盖即可；写入失败时 stderr 直接给出备份文件名 |
| 对账单 | 引擎默认**不覆盖**同名文件，自动写 `_v2`（stdout 标 `[覆盖→…_v2.xlsx]`）；不会误删历史 |
| 确认单与附件 | `_确认记录/` 按时间戳归档（毫秒 + 避让，不覆盖），可据此重放一次写入；定位由 A3.5 的 `locate_confirm.py` 自动完成，无需用户搬文件 |
| 误提交 | 从 `_备份/` 取上一版覆盖主档；`_确认记录/` 归档不动（作为审计痕迹保留） |
| 引擎半成品 | 写盘为 `*.tmp.xlsx` → `os.replace`，失败自动清理；目标文件不会留下半成品 |
| `08-复核记录` / 复核锁 | 复核后再保存会使锁失效；修正数据后重新出账、重新生成复核包并重评（`--apply` 会更新 08 表与锁）。**不要手工删锁来「通过」** |
| `_数据映射.json` | 删除或替换即回退到「无映射」原行为；已确认版本归档在 `_确认记录/映射_*.json` |
| 主档修复（`--fix-master`） | 从 `_备份/` 毫秒时间戳副本覆盖；修复只改表名 / 列名 / 顺序，不动单元格值 |

回滚后务必重跑一次对账自检，确认数字与回滚前一致或有明确差异解释。

## 三条硬规矩

1. **不用内置兜底路径**。引擎在无配置时直接中止（exit 1、stdout 0 字节），避免把测试结果写进客户目录。
2. **不在客户目录里做实验**。试跑用 `load_master.py ... --out /tmp/xxx.xlsx` 指定输出（`recon_engine.py` 本身无参数）。
3. **写库前必看 dry-run**。`apply_contract.py` 默认只打印差异，确认无误再加 `--write`。
