# 复核协议（L6 LLM 语义复核）

本文件是给**执行复核的 LLM** 的操作手册，也是 L6 的判定与留痕契约。脚本侧只做结构校验与落盘，**不调用任何外部模型**；复核结论由当前 harness 的 LLM 负责。R1–R10 的措辞与复核包 / 报告 schema 是本协议的唯一来源。

## 交付时序（交付前必过）

```
B2 引擎 → 8 表对账工作簿
  → make_review_packet.py → 复核包（packet JSON / MD）
  → 当前 harness 的 LLM 按 R1–R10 复核 → 报告 JSON
  → apply_review.py --apply → 08-复核记录 + _复核记录/复核锁.json
  → apply_review.py --check → 「复核有效」
  → 交付
任何一次保存 → 复核锁失效 → 必须重新生成复核包并重评
```

```bash
# 1) 生成复核包（CLI：<工作簿.xlsx> [--master _主档.xlsx] [--out packet.json] [--md packet.md]）
python3 "$SKILL_DIR/scripts/make_review_packet.py" "<工作簿.xlsx>" --master "<_主档.xlsx>" \
    --out /tmp/复核包.json --md /tmp/复核包.md

# 2) 由当前 harness 的 LLM 按 R1–R10 复核，产出 报告.json（schema 见下）

# 3) 落盘（默认 dry-run；--apply 与 --check 互斥；可选 --report-dir 指定归档目录）
python3 "$SKILL_DIR/scripts/apply_review.py" "<工作簿.xlsx>" "<报告.json>" \
    --packet /tmp/复核包.json --apply

# 4) 交付前校验（--check 可省略 <报告.json>；--report-dir 同时决定报告与复核锁位置，--check 需传同一参数）
python3 "$SKILL_DIR/scripts/apply_review.py" "<工作簿.xlsx>" --check
```

**无文件写权限的 harness**：跳过第 3/4 步，把复核包与报告 JSON 一并交给用户归档，并明确告知 verdict；不得声称「复核有效」。这种复核**不构成审计意见**。

## 复核包（packet）结构

schema `dealer-settlement/review-packet@1`，除 `generated_at` 外确定性输出。脚本按 00/01/02/05/06 的标签关键词取数；**取不到写 `null` 并进 `warnings`，绝不臆造 0**。

| 字段 | 说明 |
|---|---|
| `schema` / `generated_at` | 版本标识 / ISO8601 生成时间 |
| `workbook{path,sha256,size}` | 被复核工作簿与哈希（复核锁的基准） |
| `master{path,sha256}\|null` | 主档（传入时） |
| `sources[{role,path,sha256}]` | 三份源导出（jia / sales / inventory） |
| `period` / `asof` | `period` = `{"start":"2026-10-01","end":"2026-10-31"}`（对象，可为 `null`）；`asof` = `"2026-11-02"`（YYYY-MM-DD 字符串，可为 `null`）。**不要写成 `"202610"`**；带 `--packet` 时脚本会比对报告与复核包的 period（两端同为对象才严格比对，形态不同仅警告） |
| `sheets[{name,rows,cols}]` | 工作簿结构 |
| `figures{opening_qty,opening_amount,settled_qty,settled_amount,diff_qty,diff_amount,addback_qty,addback_amount,tiehua_total,closing_inventory_value,period_end}` | 关键数（只作索引入口，必须回表核对）；`period_end` = 期间末日 YYYY-MM-DD，识别不到为 `null` |
| `sku_rows[{bar,name,opening_qty,settled_qty,settled_amount,diff_qty,unit_price}]` | SKU 级明细 |
| `tiehua_rows[{bar,name,settled_qty,standard,amount}]` | 贴花明细 |
| `claims[{sheet,cell,text,numbers[]}]` | 文字断言句及其中的数字 |
| `cross_refs[{sheet,cell,text,refs[]}]` | 「详见附表 NN」类交叉引用 |
| `contract{no,method,basis,objection_days,signback_days,pay_day_text}\|null` | 合同条款（R9 用） |
| `redline_scan[{id,pattern,hits[{sheet,cell,text}]}]` | 红线措辞正则扫描；**命中只报告，不下结论** |
| `checklist[{id,item}]` | R1–R10 清单 |
| `warnings[]` | 取数缺失 / 歧义提示 |

复核时以 packet 为索引入口，**必须回工作簿核对原文与数字**；packet 缺失项按「不适用」处理并写明理由。

## 报告 JSON 结构

schema `dealer-settlement/review-report@1`：

| 字段 | 说明 |
|---|---|
| `schema` | 固定 `dealer-settlement/review-report@1` |
| `reviewer{name,model}` | 复核人 / 模型标识 |
| `reviewed_at` | ISO8601 |
| `workbook_sha256` | 必须等于工作簿当前 sha256（即 packet.workbook.sha256） |
| `period` | 期间（可为 `null`） |
| `verdict` | `通过` / `有条件通过` / `不通过` |
| `checklist[{id,result,note}]` | R1–R10 全覆盖；result ∈ `通过` / `不通过` / `不适用` |
| `findings[{level,category,sheet,cell,claim,evidence,suggestion}]` | level ∈ `阻断` / `警告` / `提示`；evidence 必须给具体数字 / 原文 |
| `summary` | 结论摘要；`不通过` / `有条件通过` 必须非空 |

脚本强制的一致性规则：

- `workbook_sha256` 与当前工作簿不一致 → 拒绝；
- checklist 缺 R1–R10 任一项 → 拒绝；未知 id → 警告；
- 存在 `阻断` finding ⇒ verdict 必须 `不通过`；
- 无阻断但有 `警告` finding ⇒ verdict 不得为 `通过`；
- `不通过` / `有条件通过` 的 summary 必须非空。

## R1–R10 操作手册

### R1 六条恒等式逐条复算（数量/金额）

- 查：`01-对账单`「一、本期结算明细」「二、铺货余额结转」、`02-库存差异表`、`00-对账说明` KPI。
- 核：数量 `q0 = q10 + theo`、`adj = act + q11`、`diff = adj − theo`；金额 `OPEN − settle = BOOK_END`、`BOOK_END − ADJ + diff_amt = 0`、`ADJ − ACT − NOV = 0`；逐 SKU 汇总与合计行一致。
- 判据：任一式金额偏差 > 0.01 元或数量不等 → **阻断**（category：恒等式）。

### R2 合计=明细之和（00/01/02/05/06 跨表一致）

- 核：01 结算明细合计 = 00「本月应结算金额」；02 差异明细合计 = 00 / 01 的差异金额；05 各门店列合计 = 总销量；06 库存合计 = 02 调整后结存；同一指标在各表一致。
- 判据：任一合计不一致 → **阻断**。

### R3 贴花合计独立复算（数量×标准，SCD2 期间正确）

- 查：01「三、贴花费用」逐 SKU；主档「贴花」表（packet 提供 master 时）。
- 核：每行 `动销数量 × 贴花标准 = 金额`；合计 = Σ；标准取**对账期末日**生效版本（同条码同一时点仅一条有效记录）；非结算类不参与；导出日前已销售部分贴花归下期；与 00「四、主要结论」第 7 条一致。
- 判据：算错、取错版本、区间重叠未报 → **阻断**。

### R4 对账单 ①–⑦ 金额结转逐式成立

- 查：01「二、铺货余额结转」。
- 核：`① − ② = ③`、`③ − ④ = ⑤`、`⑤ + ⑥ = ⑦`；⑥ 与 02 差异金额一致；⑦ 与 06 库存合计一致。
- 判据：任一式不成立 → **阻断**。

### R5 文字断言与数据一致（结论句中的数字、SKU 数、件数）

- 查：00「四、主要结论」、01「四、对账说明」、02「四、差异结论与处理建议」。
- 核：句中的金额 / 件数 / SKU 数 / 百分比与表内实算一致；「N 个相符」= 实际行数；「差异集中在…」= 02 差异 SKU 列表。
- 判据：断言与数据不符 → **阻断**（文字错误会误导签约）。

### R6 交叉引用真实存在（「详见附表 NN」确有该数）

- 查：packet `cross_refs` 与正文。
- 核：被引用的附表存在且有对应数值 / 明细；编号未错位。
- 判据：指向不存在或数字不符 → **警告**；若引用的是关键金额 → **阻断**。

### R7 口径披露完整（数据覆盖期间、期初口径、差异率分母、非结算桶）

- 核：流水覆盖期间与缺日已写明；期初口径（本期铺货 / 上期结转）已标注；差异率分母明确；非结算桶件数与「不参与本期结算」已说明；日期口径与 `--asof` 一致。
- 判据：缺任一项 → **警告**；关键口径（覆盖期间 / 期初）缺失且可能误导 → **阻断**。

### R8 红线检查（不作归因、不称实盘、不臆断税率、贴花兑付不替用户决定等）

- 查：packet `redline_scan` 命中项 + 全文措辞。
- 核：无「初步判断为乙方漏报 / 故意 / 责任」等归因；库存写「库存（系统导出）」不写「实盘」；税率写「以实际开票资料为准」；贴花兑付不替用户决定；「减：」行填正值；金额右对齐两位小数。
- 判据：归因 / 实盘 / 臆断税率 → **阻断**；格式类 → **警告**。命中词不等于违规，必须看上下文。

### R9 合同条款与主档/合同原文一致（结算方式/基数/异议期/签回期/付款日）

- 核：01 第四条与 00 事项中的条款 = 主档合同表 / 合同原文；主档缺项时输出「合同约定的…」「（主档未登记，以合同为准）」且没有印演示值；合同编号一致。
- 判据：条款与合同不符 → **阻断**；占位但未标注来源 → **警告**。

### R10 异常与差异解释充分（差异集中在哪些 SKU、是否需人工核对，未编造原因）

- 核：差异 SKU / 件数 / 金额已列示；明确「不作归因 / 待双方核对」；异常（缺条码、未建档、负库存等）有去向或待办；没有编造原因。
- 判据：编造原因 → **阻断**；差异未列示或说明不充分 → **警告**。

## 判定与阻断

| 情形 | verdict |
|---|---|
| 存在 ≥ 1 条 `阻断` | 必须 `不通过` → **不得交付** |
| 无阻断、存在 ≥ 1 条 `警告` | 只能 `有条件通过`（summary 写明条件与责任方） |
| 无阻断、无警告（或仅提示） | `通过` |

- **不通过**：修正数据 → 重新出账 → 重新生成复核包 → 重评；不能只改报告。
- **有条件通过**：交付前把「条件」明确告知用户并留痕（08 表 summary）。

## 留痕与哈希绑定

- `08-复核记录`（工作簿第 9 张表）：复核人 / 模型 / 时间 / 结论 / 被复核哈希 / 报告名 / 清单结果表（R1–R10）/ 问题表（findings）/ 免责声明。
- `<工作簿目录>/_复核记录/`：报告 JSON 与同内容 MD 归档；`复核锁.json {pre_sha256, post_sha256, verdict, report, applied_at}`。
- `--check` 通过条件：08 表与复核锁存在；08 记录的 `pre_sha256` 与锁一致；当前工作簿 sha256 == 锁 `post_sha256`；verdict ∈ {通过, 有条件通过}。全满足打印「复核有效」。
- 任何保存（含手工另存）都会改变 sha256 → 复核锁失效 → 不得交付，必须重评。
- `--apply` 重复执行幂等；不通过时只归档报告、不写 08 表、不改写工作簿，退出码 1（正常阻断，不得绕过）。
- **dry-run 与退出码**：默认 dry-run 对任何报告（包括 verdict=`不通过`）只打印校验计划并返回 0；只有 `--apply` 才真正落盘并返回 1。

## 外部工作簿复核（无复核包）

只有一份来路不明的工作簿、没有复核包时：用 `openpyxl` 读全部单元格与合并区（公式读原式，不读缓存值），按 R1–R10 直查；输出同一 schema 的报告 JSON（`workbook_sha256` 自行计算）供人工归档；不写 08 表、不声称「复核有效」。这种复核**不构成审计意见**。
