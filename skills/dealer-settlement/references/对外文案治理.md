# 对外文案治理（甲方立场 / 可公开）

> 定位：这份文档约束**会印到给乙方的单据上的每一个字**。规则来自两轮四路逐单元格审计的定稿结论。

## 1. 三条基本原则

1. **甲方立场**：以甲方陈述事实、提出确认要求；不替乙方解释其流程、不自我否定、不把甲方内部制度写成乙方命令。
2. **官方、专业、简洁**：只写与本节主题直接相关的内容。讲试用装就不要出现正装数量；不重复、不含糊、不情绪化。
3. **零内部信息**：内部系统名、文件名、出数规则、费用核算目的、考核指标、两套台账打架的披露、作者痕迹，一律不进单据。

## 2. 内部通道与对外通道

```
内部（_口径确认.json / _确认记录/ / 对话）        对外（xlsx / PDF）
出数规则文本、依据、内部用途、系统名        →      只有结果数字
internal_only[]                            →      不出现
disclosure_whitelist[] / golden 文案        →      唯一允许的措辞来源
```

**只出数字**：`乙方使用 5 / 27` 这类数字由用户私下规则算出，规则文本进 `internal_only`，单据上只有数字，并固定措辞「由乙方核对确认」，**不得写成「乙方报告使用」「乙方申报使用」**，也不得写「未经乙方确认」「不认定」等自我否定。

`assets/copy/对外文案.json` 是唯一文案真源，含三级禁止词表与 golden 句库。AI 不得在对话中自行生成或改写对外措辞。

## 3. 禁止词三级表

词表全文在 `assets/copy/对外文案.json`，由 `scripts/check_public_copy.py` 机械扫描。

**L1 绝对禁止（命中即阻断）**

| 类 | 例 |
|---|---|
| 内部系统 / 文件名 | BIP、YONICE、ERP、`*.xls*`、主档、清洗、挂账表、商品分类表、物料属性、未结算数量（作源表列名时）、源数据核对记录 |
| 内部目的 / 考核 | 费用核算、供费用、归集费用、财务另行确认、动销保障、占期初未结算货值 |
| 内部出数规则 | 1:1、每个正装商品、按 124 件折算、FIFO、先进先出、按已出库即计列 |
| 自我否定 / 替乙方说话 | 未经乙方确认、不认定、本表不作归因、不作判定、乙方是否入库、补报后可重算、不推测效期 |
| 越界命令 | 请按先进先出、优先动销、书面申请退回、请确认批次核销、请在挂账表补、重跑 |
| 非滚动台账术语 | 甲方出库、调拨出库、本期出库、出库数量、乙方报告使用 |
| 文档属性 | `KentQi`、`openpyxl`（由 A4 专管） |

**L2 需人工裁决**：`正装`（08 表不应出现；其余表需确认是商品名一部分）、`占比`（列名允许、KPI 禁止）、`收到后`（只允许出现在异议期句）、`确认后`（回寄与付款起算点必须一致）、`日前`（允许「导出日前已销售」，禁止绝对付款日）、`双方另行`。

**L3 允许但限定上下文**：`甲方期初`、`期间发货`、`乙方使用`、`甲方期末`、`结转下期`、`不参与货款结算`、`未纳入本期结算范围`、`按合同约定执行`、`如有差异请附明细说明`、`签章确认`。

扫描范围：全部单元格（含公式内字符串）、页眉页脚、文档属性（`docProps/core.xml` + zip 层）、定义名称、批注、工作表名、打印区、隐藏行列、SKILL.md frontmatter。

## 4. 机械断言 A1–A6

`check_public_copy.py` 在保存后、交付前执行，不依赖 LLM 语义判断：

| # | 断言 | 失败 |
|---|---|---|
| A1 | L1 禁止词全簿零命中 | exit 1，给命中单元格坐标与词 |
| A2 | `internal_only[]` 内容零泄漏 | exit 1 |
| A3 | `expiry.enabled=false` 时全簿零效期字样 | exit 1 |
| A4 | 文档属性无作者 / 工具痕迹 | exit 1 |
| A5 | 增量模式 `frozen_sheets` 逐格零差异（值、公式、格式、合并区、行高列宽、打印定义） | exit 1，指出变化单元格 |
| A6 | 附表编号与交叉引用一致，无悬空「附表 NN」 | exit 1 |

`clean_properties()` 用 zip 成员级补丁清除 `dc:creator` / `cp:lastModifiedBy` / 时间戳——openpyxl 保存时会回填，必须在**最后一次保存之后**调用。

## 5. 定稿文案模板（golden）

完整句库见 `assets/copy/对外文案.json` 的 `golden`。关键几条：

| 键 | 定稿原文 |
|---|---|
| `copy.08.subtitle` | 本表所列商品不参与货款结算　·　请乙方核对期初、期间发货、使用与期末数量后签认 |
| `copy.08.note.1` | 1. 试用装、中小样不参与货款结算，本期单独列示，供双方核对数量。 |
| `copy.08.note.2` | 2. 「甲方期初」为上期结转数量，本期为首期，期初为 0；「期间发货」为本期发出数量；「乙方使用」为本期使用数量，由乙方核对确认。 |
| `copy.08.note.3` | 3. 「甲方期末」＝期初 ＋ 期间发货 － 乙方使用，结转下期。 |
| `copy.08.note.4` | 4. 请乙方核对下列数量并在签章回执中书面确认；如有差异，请附明细说明。 |
| `copy.09.basis.4` | 4. 本表仅提示剩余效期，供双方安排动销，不构成对乙方仓储作业的要求；具体处理方式由双方另行协商。 |
| `copy.01.note.5` | 乙方应于收到本对账单后 {异议期}内书面提出异议，逾期未提出视为确认；确认后 {回寄期}内将签章原件寄回甲方。 |
| `copy.01.note.6` | 付款期限：乙方签章确认后 {付款期}内将上述款项汇入甲方指定账户；部分异议不影响无争议款项如期支付。 |

时限一律从主档「合同」表读取变量，不硬编码天数，也不写已过期的绝对日期；异议期用「收到后」，回寄与付款都用「确认后」。

## 6. 模块开关与文案键

| 文案键 | `expiry.enabled=false`（本期） | `true`（下期） |
|---|---|---|
| `sheet.09` / `copy.09.*` | 整表不创建 | 创建 09 表，用全套 golden |
| `copy.00.conclusion.efficacy` | 不渲染，结论止于 8 | 渲染，指向附表 09 |
| `copy.00.ask.efficacy` | 不渲染，待确认止于 4 | 渲染「近效期库存处理」 |
| `copy.00.annex.09` | 不渲染，清单止于附表 08 | 渲染 |
| `copy.01.note.efficacy` | 不渲染，说明止于 7 条 | 渲染中性提示 |
| `copy.08.*` / 结论 8 / 待确认 4 / 附表 08 | **恒定渲染** | **恒定渲染** |

关闭时的硬断言：全簿 `效期 / 批次 / 到期 / 临期 / 预警 / 剩余月数 / FIFO` 命中数 = 0，无 09 表名，无悬空「附表 09」。

## 7. L6 立场检查（P1–P10）

写进复核包，由 L6 LLM 逐项判「通过 / 不通过」；任一阻断项不通过即 `verdict=不通过`。

| # | 检查项 | 判定标准 |
|---|---|---|
| P1 | 立场一致性 | 无「乙方是否 / 取决于乙方 / 本表不作归因 / 未经确认」 |
| P2 | 内部系统 / 文件名零泄露 | L1 对应类命中数 = 0 |
| P3 | 内部出数规则零泄露 | 规则词命中 = 0，数字单元格均为数值型 |
| P4 | 内部目的 / 考核零泄露 | 对应类命中 = 0 |
| P5 | 本节主题纯净度 | 08 表无「正装 / 1,776 / 124 件」（若保留对应列，须有书面裁决单） |
| P6 | 滚动台账术语 | 四栏表头齐全、恒等式句存在、无「出库 / 发货」旧术语 |
| P7 | 不越界命令 | 无「优先动销 / 申请退回 / 请按先进先出」；近效期段含「由双方另行协商」 |
| P8 | 时限闭环 | 异议期用「收到后」，回寄与付款同为「确认后」，无绝对日期 |
| P9 | 表号与引用一致 | 08 = 试用装、09 = 效期；所有「附表 NN」可解析 |
| P10 | 公开性 | 4 张标红、文档属性清空、L1 全簿零命中 |

## 8. 维护责任

- `assets/copy/*` 由甲方业务 / 合规口径审批，改动需双人签字并记入 `assets/copy/CHANGELOG.md`。
- 机制代码（`check_public_copy.py` / `apply_v17.py`）由 skill 维护者负责，**不得改文案内容**。
- 每次文案改动须更新保证快照并重跑 `examples/v17_demo.py`。
- 复核锁把工作簿哈希与文案门禁结果绑定；审计后被改回内部口径会使锁失效，强制重评。
