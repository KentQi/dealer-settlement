# 铺货代销全流程：建档 → 确认 → 对账 → 校验 → 复核

## 0. 运行约定（跨 harness，先读）

**SKILL_DIR** = 本 `SKILL.md` 所在目录的绝对路径（其下为 `scripts/` `references/` `assets/`）。下文命令中的 `$SKILL_DIR` 都指它。每次会话只确定一次，按当前 harness 支持的方式任选：

1. harness 提供 skill 根目录路径（上下文变量或环境变量）→ 直接使用；
2. 已知安装位置 → 自行赋值，如 `SKILL_DIR=/path/to/skills/dealer-settlement`（示例，按实际替换）；
3. 都不确定 → 在文件系统中定位本 `SKILL.md`，取其父目录。

验证：`ls "$SKILL_DIR/scripts"`（PowerShell：`Get-ChildItem "$SKILL_DIR\scripts"`）能列出 `extract_contract.py`、`load_master.py`、`recon_engine.py` 等脚本即正确。

- **Python**：下文统一写 `python3`；Windows 用 `py -3`（或 `python`，用 `--version` 确认 ≥ 3.9）。
- **依赖（仅首次）**：`python3 -m pip install openpyxl xlrd pdfplumber`（PowerShell 同形）。
- **路径**：一律用绝对路径或 `$SKILL_DIR/...`；**不要假设**当前工作目录就是 skill 目录或客户目录。
- **能力与回退**（当前 harness 有则该能力、无则回退；不假定任何具体工具名）：
  - 文件展示 / 打开：有展示或打开能力 → 把生成的文件直接呈现给用户；否则给出**绝对路径**，让用户用浏览器（HTML）、Excel / WPS / LibreOffice（xlsx）手动打开。
  - 结构化提问 / 确认卡片：有且离散决策 ≤ 4 项 → 可用；否则在回复中逐项提问。合同字段确认默认走 HTML 确认页，**不依赖** harness 交互能力。
  - **确认单去向**：确认页提交后，确认单通常在浏览器下载目录（用户点过「存到客户目录」时在客户目录）；助手用 `locate_confirm.py` 自动定位（阶段 A3.5），**不要让用户搬文件**，也不要向普通用户解释文件格式。
  - 本地文件读写：有读取能力 → 直接读；否则让用户提供路径或上传附件。
  - LLM 语义复核：由**当前 harness 的模型**执行，脚本不调用任何外部模型；harness 无文件写权限时，至少输出复核报告 JSON 由用户归档（详见 [references/复核协议.md](references/复核协议.md)）。
  - 网络：脚本不联网；除首次 pip 安装依赖外无需网络。

**Windows / PowerShell 等价写法**（以 B1 / B2 为例；其余命令同理：`python3` → `py -3`，路径分隔符可用反斜杠或正斜杠）：

```powershell
$SKILL_DIR = "C:\path\to\dealer-settlement"          # 按实际替换
$env:RECON_CFG = & py -3 "$SKILL_DIR\scripts\load_master.py" "C:\客户\_主档.xlsx" --period 202610 --asof 2026-11-02
py -3 "$SKILL_DIR\scripts\recon_engine.py"
```

若 `load_master.py` 失败，`$env:RECON_CFG` 为空，引擎随即中止（不会生成文件）。

**阶段 G 是第 0 道闸**：任何出账、补表、换源表之前，先完成业务口径确认（见 §2）。
不过闸不得生成任何 .xlsx。

## 1. 必要文件（输入清单）

### 1.1 客户主档 `_主档.xlsx`（必需，放客户根目录，固定文件名）

六张工作表。下表标注引擎是否硬性依赖；字段设计细节按需读 [references/客户主档设计.md](references/客户主档设计.md)：

| 表 | 作用 | 关键字段（缺失后果） |
|---|---|---|
| 主体 | 甲乙双方抬头与收款账户 | 角色、名称、统一社会信用代码（引擎硬性）；甲方另需开户行、账号（引擎硬性） |
| 合同 | 结算与账期口径 | 合同编号（引擎硬性，用于输出抬头）；结算方式 / 结算基数（进入 00·01 结算口径，缺失写「主档未登记，以合同为准」）；异议期 / 签回期（进入双方确认时限，缺失写「合同约定的…」）；付款日（进入付款期限并决定 `--pay` 缺省日，缺失按次月 5 日）；起始 / 终止 / 价格附件（人工核对与摘要用） |
| 价格 | 供货价（带生效区间） | 商品条码、供货价、生效起、生效止（只用于「挂账单单价 vs 主档」交叉校验告警，不参与结算取价） |
| SKU | 商品主数据与结算属性 | 商品条码、标准品名、结算属性（**引擎硬性**：空 / 未知 → 阻断，绝不默认结算类） |
| 期间 | 历史对账索引 | 期间、数据基准日、结算 / 差异 / 贴花金额、贴花兑付方式（**脚本不读写**；每期对账后由助手或人工追加一行） |
| 贴花 | 销售奖励标准（带生效区间） | 商品条码、贴花标准、生效起、生效止。**表存在时**：本期有动销的每个 SKU 必须有当期记录（显式 0 也算），缺失 / 脏值 / 区间重叠 → 阻断；**整表不存在** → 跳过贴花模块并提示 |

没有主档 → 用 `make_master.py` 生成六表模板（演示行，需整行替换），或走阶段 A 从合同建档。

### 1.2 当期三份导出（必需，放月份目录 `YYYYMM/`）

| 关键词（文件名须含） | 对应 | 例 |
|---|---|---|
| `挂账` | 甲方 ERP 未结算挂账 | 「甲方-20261102ERP挂账.xls」 |
| `销售数据`（或 `销售`，但不可含 `库存`） | 乙方当期动销流水 | 「乙方-202610销售数据.xlsx」 |
| `库存` | 乙方库存（＋次月已销表） | 「乙方-20261102库存+当月销售.xlsx」 |

可选源（没有就按「未提供」处理，不会报错，也不会推测）：

| 关键词（文件名须含） | 对应 | 例 |
|---|---|---|
| `效期` / `批次` / `生产日期` | 甲方批次效期表（挂账表无批次列时使用） | 「甲方-20261102批次效期.xlsx」 |
| `使用` / `领用` | 乙方试用装 / 中小样 / 配赠使用明细 | 「乙方-202610试用装使用.xlsx」 |
| `条码对照` / `编码对照` / `物料编码` | 商品条码 ↔ 物料编码对照（挂账表无条码列时必填） | 「商品条码-物料编码对照.xlsx」 |

甲方挂账表可选带三列，引擎自动识别（缺列则按旧行为）：

| 列名（含关键词即可） | 取值 | 作用 |
|---|---|---|
| `批次号` / `批次` / `批号` | 任意文本，可写成 `批次号/有效期` 合体（如 `R0320B11/20290319`） | 批次维度；合体时自动拆成批次号与有效期；同品名多批次按行展开 |
| `有效期` / `到期日` / `失效日期` | 日期 / Excel 日期 / `YYYY-MM-DD` | 效期分档；也可只给 `生产日期`+`保质期` |
| `物料属性` / `物料类型` | 正装 / 试用装 / 中小样 / 配赠 / 陈列 | 非正装不参与货款结算，另出附表 09 |
| `物料编码` / `客户物料号` / `物料编号` | 任意文本 | 经「条码对照表」映射成商品条码；挂账表无条码列时按此匹配主档 |

- `.xls` 用 `xlrd` 读；`.xlsx` 用 `openpyxl`（`openpyxl` 不支持 `.xls`）。
- 表名与列名不写死：引擎按关键词找工作表、按表头关键词定位列。找不到或多张候选时会**中止并列出候选**，不会猜。
- 客户根目录混放导出有取错期间的风险：脚本优先用 `YYYYMM/` 目录，根目录有导出但无月份子目录时直接中止。

### 1.3 合同原件（阶段 A 需要）

支持 `.docx` / `.pdf` / `.xlsx` / `.xlsm` / `.txt` / `.md`（`.doc` / `.wps` 请先另存为 `.docx`）。优先级：`.docx` 电子版 > 有文本层的 PDF > 扫描件。扫描件无文本层会被识别并提示（`needs_ocr: true`），不会静默返回空字段。

### 1.4 目录结构

```
<客户根目录>/                    例：.../铺货代销客户/示例经销商有限公司/
├── _主档.xlsx                  ← 六表（主体/合同/价格/SKU/期间/贴花）
├── _合同摘要.md                ← 自动生成
├── _确认页_YYYYMMDD.html       ← 自动生成
├── _确认记录/                  ← 确认单与附件归档（留档凭据，勿删）
├── _备份/                      ← 每次写库前的主档快照（毫秒时间戳，不覆盖）
└── YYYYMM/                     ← 期间目录，放三份导出
```

## 2. 开工前两道闸（都过才能出账）

**闸一 · 结构**（阶段 0）：表名 / 列名 / 列序漂移 → `inspect_schema.py` 探查 → 用户逐项裁决 → `_数据映射.json`。无漂移可跳过。

**闸二 · 业务口径**（阶段 G，1.7.0 起强制）：**任何业务口径未逐项确认前，不得出账、不得补表、不得生成任何 .xlsx**。答案写入客户根目录 `_口径确认.json`；缺项即 `exit 1`、stdout 0 字节、stderr 给中文业务语言问卡。四场景问卡、字段 schema 与哈希链见 [references/口径确认协议.md](references/口径确认协议.md)。

必须走：首次建档 / 每月出账 / 增量补表 / 换源表结构 / 模块开关变化（含「本期关效期、下期开」）/ 用户出现纠正信号（「你没看懂」「不要写到纸面上」「这个规则是我定的」）。可跳过：同一期间 + 同一口径文件 + 同一源文件的幂等重跑、只读复核、纯结构探查；跳过时仍校验哈希。

每期还需确认 5 项操作事实（已并入问卡）：① 期间与基准日；② 有无非动销变动；③ 上期差异是否结转；④ 是否调价 / 调贴花；⑤ 有无新 SKU / 新门店。**前两项可从目录推断一部分；后三项不得默认「无」，必须逐项确认。**

用户给出的内部规则、出数依据、内部用途一律进 `internal_only`，**只准写入确认记录，绝不准进入任何单据**（见 §6 与 [references/对外文案治理.md](references/对外文案治理.md)）。

## 3. 工作流

### 阶段 0：结构自检与映射确认（按需触发，用户确认门禁）

**触发**：首次接新客户 / 换 ERP；引擎报 `[中止] 未找到含…的工作表` 或 `[自检未通过] 数据表未找到含…的列`；用户说「表名 / 表头 / 列顺序不一样」。无漂移时直接跳过，不产生任何文件。

**强制流程（用户确认不可跳过）**：

1. **自动识别（只读）**：`python3 "$SKILL_DIR/scripts/inspect_schema.py" "<客户根目录>" --out /tmp/探查.json --md /tmp/探查.md`；
2. **向用户展示**「实际名称 → 规范字段 / 置信度 / 待裁决项 / 影响」（表格化，话术模板见 [references/数据映射与结构探查.md](references/数据映射与结构探查.md)）；**低置信项必须逐项问，禁止代替用户决定**；
3. 用户逐项裁决后生成 / 编辑映射 JSON（结构见同一 reference）；
4. **预览**：`python3 "$SKILL_DIR/scripts/apply_mapping.py" "<客户根目录>" "<映射.json>"`（默认 dry-run，打印将写入的内容与影响）；
5. **确认后落盘**：`python3 "$SKILL_DIR/scripts/apply_mapping.py" "<客户根目录>" "<映射.json>" --write --confirmed-by "<确认人>"` → 写 `_数据映射.json`，副本归档 `_确认记录/`；未经用户确认不得加 `--write`；
6. 重跑 B1 / B2，引擎按映射取表与列。

**主档修复（可选）**：表名 / 列名 / 顺序漂移也可先修主档——`python3 "$SKILL_DIR/scripts/apply_mapping.py" "<客户根目录>" "<映射.json>" --fix-master [--fix-order]` 先 dry-run，确认后加 `--write --confirmed-by`；写前自动备份到 `_备份/`（毫秒时间戳）。

**铁律**：永不修改三份源导出（只写映射）；不得凭文件名 / 位置猜字段；映射确认 ≠ 数据正确性背书。

### 阶段 A：合同建档（一次性 + 增量）

```bash
# A1 抽取候选字段（每字段带 value / evidence / confidence）
python3 "$SKILL_DIR/scripts/extract_contract.py" <合同文件> -o /tmp/contract.json

# A2 生成摘要（主档已存在时；新客户可跳过，A5 再跑）
python3 "$SKILL_DIR/scripts/make_digest.py" <_主档.xlsx>

# A3 生成确认页（抽取脚本固定输出 22 项候选字段，逐项确认走 HTML，不要用聊天逐问）
python3 "$SKILL_DIR/scripts/make_confirm_html.py" /tmp/contract.json <_主档.xlsx>
#   → 展示/打开 _确认页_YYYYMMDD.html（默认生成在主档同目录；无展示能力时给绝对路径，用浏览器打开）；
#     用户逐项确认、填「确认人」后点「提交」，回对话说一声「好了」即可。

# A3.5 自动定位确认单（用户说「好了」之后执行；无需用户搬文件、不要解释文件格式）
python3 "$SKILL_DIR/scripts/locate_confirm.py" --customer "<客户根目录>" --max-age-minutes 120 --json
#   退出 0 → 取 JSON 的 chosen.path，记为 CONFIRM 后进入 A4（人话摘要里也有「文件 : <绝对路径>」行）；
#   退出 2 → 多份候选：JSON 的 chosen 是最新一份，用它在并明确告诉用户「用了最新提交的那份」，或一句话请用户确认；
#   退出 1 → 一句话问用户（确认页是否已点「提交」？是否换了浏览器 / 电脑？），必要时加
#              --dir "<下载目录>" 兜底再试。
CONFIRM="<退出 0 时 JSON 的 chosen.path>"

# A4 写库（先 dry-run 看差异，再 --write；写库自动类型校验 + 备份 + 归档确认单）
python3 "$SKILL_DIR/scripts/apply_contract.py" <_主档.xlsx> "$CONFIRM"
python3 "$SKILL_DIR/scripts/apply_contract.py" <_主档.xlsx> "$CONFIRM" --write

# A5 重跑摘要（供人工核对与归档；引擎直接读主档，不读摘要）
python3 "$SKILL_DIR/scripts/make_digest.py" <_主档.xlsx>
```

A3 确认门槛不可跳过：抽取结果是候选，不是结论。冲突项（主档现值 ≠ 候选值）在确认页由用户裁决；已确认单里的冲突按确认值写入。待核项留空不猜。

**A3.5 红线**：**不得要求用户移动 / 复制 / 重命名确认单文件，也不得向普通用户解释 JSON 等文件格式**；找不到时用一句人话问（确认页是否已点「提交」？是否换了浏览器 / 电脑？），必要时用 `--dir` 指定下载目录再定位。多份候选时，助手用最新的一份并明确说「用了最新提交的那份」，或一句话请用户确认。

### 阶段 B：月度对账

```bash
# B1 主档 → 配置（自动定位月份目录、识别三份源文件）
export RECON_CFG=$(python3 "$SKILL_DIR/scripts/load_master.py" "<客户根目录>/_主档.xlsx" \
    --period 202610 --asof 2026-11-02)
#   --period 必须 6 位年月；--asof 是库存导出日，决定回加哪几天销售
#   --pay 付款日缺省取主档「合同·付款日」中的日期（解析不到用次月 5 日）
#   可选：--base 月份目录、--out 输出路径（自动转绝对路径）、--strict 主档不全即退出

# B2 引擎计算 + 自检（无命令行参数，只读环境变量 RECON_CFG）
python3 "$SKILL_DIR/scripts/recon_engine.py"
```

Windows / PowerShell 见第 0 节；`--out` 属于 `load_master.py`，`recon_engine.py` 本身不接受任何参数。

`RECON_CFG` 由 `load_master.py` 生成、无需手改；其结构与高级开关（`overwrite` / `allow_large_diff` / `verify_notes`）见 [references/故障与回滚.md](references/故障与回滚.md)。

**六条恒等式 + 贴花口径**

设某 SKU 期初未结算 `q0`、当期动销 `q10`、库存导出月已销 `q11`、库存导出数量 `act`（`p` 为结算单价）：

| # | 恒等式 |
|---|---|
| 1 | 结算数量 = q10（按实际动销，未动销不计） |
| 2 | 理论结存 = q0 − q10 |
| 3 | 调整后结存 = act + q11（时点回加） |
| 4 | 差异 = 调整后结存 − 理论结存（负数=短缺，正数=盘盈） |
| 5 | 结算金额 = q10 × p |
| 6 | 期末未结算货值 = 期初未结算货值 − 结算金额 |

**贴花口径（第 7 条计算规则，不是数量恒等式）**：贴花金额 = Σ(结算类动销数量 × 当期生效贴花标准)；导出日前已销售部分的贴花随其货款计入下期。

> 对账单第二节的 ①–⑦ 是**金额结转编号**，不是恒等式编号：① 期初货值、② 减本期结算、③ = ①−② 期末未结算、④ 减导出日前已销售、⑤ = ③−④ 期末理论结存、⑥ 差异（带符号）、⑦ = ⑤+⑥ 乙方库存货值。两套编号不要混用。

**时点对齐**：回加区间由「期末日+1 至导出日」计算。导出日不晚于期末时自动不回加，文案同步切换；不允许出现「正确标签 + 错误数字」。

**输出**：`00`–`07` 为结算核心（脚本生成，不要手工重排）；`08-试用装与中小样` 恒生成；`09-效期预警` 由 `expiry.enabled` 控制，本期关、下期开。表号由 `_口径确认.json` 的 `sheet_map` 决定，禁止在脚本里写死编号。关闭效期时 00 表结论 / 待确认 / 附表清单三处必须同步裁剪，全簿零效期字样。v1.7 全链路：`load_master → recon_engine → apply_v17 → 对外门禁 → PDF（可选）→ L6 复核`。原无数据时仍会生成说明页，不省略。

### 阶段 C（B3 / L6 / B4）：校验、复核与交付

1. **C1 确定性校验（B3）**：核 stderr 自检行「自检通过（残差 0.00）」，任何「⚠」转述；复算六个数（期初 / 结算 / 差异的件数与金额）；断言 `结算金额 − 差异金额（带符号） + 次月已销货值 = 期初货值 − 期末库存货值`，贴花合计独立复算。引擎已对六条恒等式逐条显式校验（不用 `assert`，`python -O` 下也不会静默失效）。
2. **C2 生成复核包**：`python3 "$SKILL_DIR/scripts/make_review_packet.py" "<工作簿.xlsx>" --master "<_主档.xlsx>" --out /tmp/复核包.json --md /tmp/复核包.md`。
3. **C3 L6 LLM 语义复核（交付前必过）**：由**当前 harness 的 LLM** 按 [references/复核协议.md](references/复核协议.md) 的 R1–R10 逐项复核（脚本不调用外部模型），产出报告 JSON；`python3 "$SKILL_DIR/scripts/apply_review.py" "<工作簿.xlsx>" "<报告.json>" --packet /tmp/复核包.json --apply` 写入 `10-复核记录`（第 11 张表；旧工作簿仍按 `08-复核记录` 兼容读取）并生成 `_复核记录/复核锁.json`。verdict 不通过 / 有阻断 finding → **不得交付**；复核后任何保存都会使锁失效，必须重评。
4. **C4 交付与登记（B4）**：交付前跑 `python3 "$SKILL_DIR/scripts/apply_review.py" "<工作簿.xlsx>" --check` 确认「复核有效」；向用户报告应结算金额、贴花金额、差异件数与金额、差异集中的 SKU、数据覆盖期间（流水缺哪几天必须说）；展示 / 打开工作簿，并在主档 `期间` 表追加一行（期初 / 结算 / 差异 / 贴花 / 状态）。

## 4. 校验体系（五层确定性校验 L1–L5 + L6 LLM 语义复核）

| 层 | 时点 | 校验什么 | 失败行为 |
|---|---|---|---|
| L1 入口 | load_master / 引擎启动 | 主档必填项（主体名、税号、合同号、账户）、三份源文件与 `master_path`（load_master 自动生成）；`--period` / `--asof` / `--pay` 格式；根目录导出劫持 | 中止，stderr 给中文原因 + 可整行复制的修复命令；**stdout 保持 0 字节** |
| L2 写库 | apply_contract 写入前 | 数值列（价格 / 数量 / 贴花金额：非负、有限、≤1e9、两位小数）、日期列（YYYY-MM-DD）、枚举列（结算属性 / 结算方式 / 结算基数 / 状态，状态含已签回、已收款）、条码列（8–14 位数字）；多行表按主键定位，不猜行 | 该字段**拒绝写入**并打印原因，其余合法字段照常；不静默转换 |
| L3 计算自检 | 引擎计算中 | ① 明细合计=按条码汇总 ② 挂账源表=归一化后 ③ 结转残差=0 ④ 贴花合计独立复算 ⑤ 库存合计非 0；差异率 ≤ 30% 阈值 ⑥ 六条恒等式（3 条金额勾稽 + 3 条数量）逐条显式校验 | `_bail` 中止；stderr 先打出已算出的六个数，便于定位 |
| L4 结构守卫 | 数据读入后 | 同条码多行挂账→中止（防动销双算）；库存按条码聚合；结算属性三态（空/未知→阻断，绝不默认为结算类）；销售表月份与期间不符→中止；销售流水缺条码、源表脏值（布尔 / 非数字 / 非有限）→中止 | 中止或聚合告警 |
| L5 输出 | 保存前后 | 新建写 `[新建] <绝对路径>`；目标已存在默认写 `_v2` 不覆盖并标 `[覆盖→<新文件名>]`；显式 `overwrite: true` 才覆盖原文件（`[覆盖]`）；写入失败时提示原因且原文件未受影响 | 保护性改名或中止 |
| L6 语义复核 | 交付前（B4 之前） | 按 R1–R10 逐项复核：六条恒等式、跨表合计、贴花独立复算、①–⑦ 结转、文字断言、交叉引用、口径披露、红线、合同条款、差异解释 | **不得交付**；修正后重新出账并重做 L6（复核锁绑定工作簿哈希，任何保存都会失效） |

校验的铁律：**缺失即阻断，不做语义兜底**。空值不会被默认成「结算类」「0 件」「件」——凡是看起来正常的静默兜底，都制造过不可发现的数据错误。L6 的铁律：**结论必须来自实算数字与原文**，不允许凭印象；**不通过不得交付**。

## 5. 计算模块（贴花 / 效期 / 促销物料）

### 5.1 贴花（销售奖励）

**定义**：贴花 = 销售结算时甲方给乙方的奖励，按「本期动销数量 × 当期生效贴花标准」计算。

**数据来源**：合同附件价格政策表（如「示例价格政策表」）的「门店贴花」列。录入主档「贴花」表：条码、标准（元/件）、生效起止、依据文件、备注。

**口径（写进对账单，不臆断）**：
- 基数 = 本期动销数量（与货款结算同一口径；导出日前已销售部分归下期，贴花随之）。
- 版本 = 对账期末日落在哪个生效区间，就取哪版标准（SCD2，与价格表同构）。
- 兑付方式 = 按双方约定：抵扣货款或单独支付。**对账单只列示计算结果，不预设应付净额；抵扣与否、开票按费用还是货款折让，均由双方书面确认，不替用户决定。**

**三态规则**：主档无「贴花」表 → 跳过模块并提示；有表 → 本期动销的每个 SKU 必须有当期有效记录（显式 0 也算），缺失 / 脏值 / 区间重叠即阻断。

**展示**：`01-对账单`「三、贴花费用（销售奖励，本期动销口径）」节——逐 SKU 明细（动销量 / 标准 / 金额 / 依据）+ 合计 + 口径说明（基数取本期结算类动销、标准取对账期末生效版本、非结算类不参与、导出日前已销部分随货款计入下期；兑付方式与开票口径由双方书面确认，不预设应付净额）；`00-对账说明`「四、主要结论」第 7 条同步汇总（仅贴花表存在时出现）。

**留痕**：每期把贴花金额与兑付方式（抵扣货款 / 分开支付 / 待定）登记进主档「期间」表对应列——这是贴花跨期追溯的唯一索引，漏登记即断链。

### 5.2 效期提示（附表 09；模块默认关闭，能力完整保留）

**开关**：由 `_口径确认.json` 的 `decisions.expiry.enabled` 控制。关闭时不生成 09 表，00 表结论 / 待确认 / 附表清单三处同步裁剪，全簿零效期字样；开启时 09 表与三处引用一并恢复。**代码、文档、演示夹具始终保留，禁止因某期不做而删除能力。**

**数据来源**：件数以甲方挂账表（结算与结存的唯一依据）为准；批次号、失效日期取自甲方批次记录（挂账表批次列，或独立 `expiry_ref` 源）。批次字段支持 `批次号/YYYYMMDD` 合写。**效期参考表的「结存主数量」不得作为结存基数，不得进入任何结算金额、库存恒等式或批次结存勾稽。**

**口径**：
- 基准日 = 数据基准日 `asof`，不是对账期末日。
- 分档按剩余**月数**，阈值由 `expiry.tiers` 配置（默认 `[32, 28, 24]` 个月）：低于 24 / 低于 28 / 低于 32 / 正常，已过期单列。月数为日历月差，不足一个月向下取整。
- 中小样件数按 `expiry.sample_qty_basis`：默认「台账期末」（取 08 表甲方期末），可选「期间发货」。
- 先进先出只用于批次展示顺序与动销安排提示，**不用于计算结存**；不得写「请按先进先出优先动销」这类把甲方制度写成乙方命令的话。
- 正装与中小样纳入效期提示；试用装不纳入。

**红线**：不得把效期表数量当结存；不做跨批次插值，不按品名或经验补效期；关闭时单据里一个效期字都不留。

### 5.3 试用装 / 中小样 / 配赠（附表 08）

**定位**：不参与货款结算、不进入六条恒等式，但须单独出表让乙方核对签认数量。甲方内部用途不得上纸面。

**四栏滚动台账**：`甲方期末 ＝ 甲方期初 ＋ 期间发货 － 乙方使用`，期末结转下期期初。期初取上期同物料期末（首期 0）；期间发货取 `item_class`（商品分类）的非正装列；乙方使用取 `_口径确认.json` 的 `usage.ledger` 既成数字。**禁止使用「甲方发货 / 出库 / 结余」等一次性口径**——本期发了，下期无法结转。

**使用量三态**：
- ① 甲方口径：规则由用户私下给出，只把结果数字写入 `usage.ledger`，规则文本只进 `internal_only`；
- ② 乙方提供：逐物料给数；
- ③ 未提供：使用与期末显示「—」，**不按 0、不按销量或经验比例推算**，并列入待确认。

**对外呈现**：表头固定「甲方期初 / 期间发货 / 乙方使用 / 甲方期末」；表内不出现正装数量、单价、金额、结算字样；含「不参与货款结算」声明与乙方签章区。「对应正装 / 本期正装销量」两列是否保留由阶段 G 决定（默认保留，需接受乙方可反推规律的风险）。

**红线**：不编造乙方使用量；不把出数规则、内部费用目的写进单据；不写「未经乙方确认」「乙方报告使用」等自我否定或误导措辞；只给数量、不算金额。

## 6. 用户操作指导（AI 应答脚本）

用户问操作问题时，按下列脚本引导，**只引导不代做**，每步给出可验证的结果：

**「我要出 X 月对账单」**
1. 确认主档在客户根目录 → 列出该目录内容给用户核对（bash `ls` / PowerShell `Get-ChildItem`，或用 harness 的文件读取能力）；
2. 让用户把三份导出放进 `YYYYMM/`（或经用户授权后由助手保存到该目录）；
3. 跑 B1 + B2，把 stderr 的自检行、六个关键数、所有 ⚠ 告警转述给用户；
4. 展示 / 打开工作簿（无展示能力时给绝对路径）：报告应结算、贴花、差异、流水覆盖期间；
5. 提醒用户在 `期间` 表登记（或问是否代登记）。

**「这是新客户，第一次做」**
1. 要合同电子版（docx 优先）→ 跑 A1；
2. `make_master.py` 建模板 → A3 确认页让用户逐项确认 → 用户在页面点「提交」后回对话说「好了」→ 助手按 A3.5 自动定位确认单并归档写库（A4，先 dry-run 再 `--write`）；全程不需要用户搬文件，也不要向用户解释文件格式；
3. 引导用户补三样 AI 拿不到的信息：甲方收款账户、税率口径、贴花标准表；
4. 再走「我要出 X 月对账单」。

**「合同里价格 / 贴花变了」**
1. 打开主档对应表，教用户**旧行补「生效止」、新行填「生效起」**，两行并存；
2. 提醒：不可回溯改历史单价 / 标准，否则往期对账不可复现；
3. **口径提醒**：当前结算单价取自甲方挂账表，主档「价格」「贴花」表用于交叉核对与贴花计算——改价后如发现挂账表单价未变，先与系统维护方核对，不要只改主档；
4. 改完重跑当期对账，核对引擎输出的价格交叉校验告警。

**「差异怎么回事 / 少了多少件」**
1. 只陈述事实：哪些 SKU、差多少件 / 多少元、占比；
2. 引导用户与乙方核对销售流水、调拨、赠品记录；
3. 明确说：本工具不作归因，结论以双方核对为准。

**「刚才填错了 / 误提交了」**
1. 主档回滚：从 `_备份/` 取时间戳最近的上一个版本覆盖；
2. 对账单回滚：引擎不覆盖同名文件（写 `_v2`），历史都在；
3. 确认单归档不动——那是审计痕迹。

**「扫描件识别不出来」**
告知：无文本层需 OCR 或手工录入；`needs_ocr: true` 已标注；建议要 docx 电子版。

**给已有工作簿增量补附表**（1.7.0 新增）：先只读盘点并回述「这份是 X 期的簿子，现在有 N 张表，对吗？」→ 发业务语言卡片确认「哪几张表一个字都不能动 / 补哪几张、编号排第几 / 00 表是否只加说明」→ 逐项确认口径（含效期这期做不做）→ 出现「你没看懂」「不要写到纸面上」等纠正信号立即丢弃草稿、只重发被纠正项 → 写 `_口径确认.json` → dry-run 展示表号、源列、对外文案、隔离清单 → 确认后生成并跑 A1–A6 断言（`01–07` 零差异、`00` 只加说明、附表整张重做、禁止词零命中、关闭效期零字样）→ 任一断言失败不交付、不覆盖。命令：`load_master.py --mode incremental --in-workbook <簿> --overwrite`，随后 `recon_engine.py` 与 `apply_v17.py`。

**导出签章 PDF**（1.7.0 新增）：`load_master.py --pdf`（可加 `--pdf-sheets 00,01,02,08`），`apply_v17.py` 在门禁通过后自动把四张打印表合成一份 `<期间>对账-签章件.pdf`；或单独跑 `python3 "$SKILL_DIR/scripts/export_pdf.py" --book <工作簿> --out <PDF>`。中文字体自动发现，找不到时按报错用 `--font` 指定。

## 7. 红线

每条都对应一类被反复验证过的失败模式。

**建档阶段（1–4）**

1. **不把未确认的抽取值写库**。抽取是候选，不是结论；`--write` 前必须经过 A3。
2. **不跨主体取字段**。联系人、电话、税号必须来自本主体段落；全局兜底抓取极易把乙方电话填成甲方。
3. **不覆盖已有值**。冲突一律上报，由用户裁决。
4. **不凭格式猜字段**。扫描件无文本层时，先告知需 OCR 或手工录入，不用文件名推测。

**判据纪律（5–6）**

5. **结算判据只能是「主档·结算属性 + 商品条码」**。乙方给的「商品分类」是其 ERP 口径，甲方侧无权威对应表，原理上不能用来区分结算 / 非结算。同一品类下常常混有结算类与非结算类单品（陈列装、赠品装尤甚），按分类过滤必然误伤大量结算品。分类字段仅作展示，且须在表头标注「（乙方系统）」。
6. **同一条码出现多笔挂账 → 硬中止**。同一产品的动销会被双算，且结转恒等式仍能凑平，事后无法发现。同理：库存同条码多行必须合计而非覆盖。

**对账阶段（7–16）**

7. **不作归因**。数据只证明「差多少」，不证明「为什么差」。禁止写「初步判断为乙方漏报」。
8. **不臆断税率**。不知道就写「税率与发票种类以实际开票资料为准」。
9. **不称「实盘」**。乙方给的是系统导出，无盘点日期与签字，一律写「库存（系统导出）」。
10. **不引未经核实的条款**。赔偿 / 责任类条款必须逐字核对合同原文并确认适用前提后才可引用，不得扩张解释或凭印象转述。
11. **「减：」行填正值**，由公式做减法，避免双重否定。
12. **差异率分母写明**，分组与合计基数不同时须在表头标注。
13. **金额列右对齐、两位小数**；合计格格式漏改会印出 5,000 而明细是 4,999.99。
14. **披露数据覆盖期间**。销售流水常缺日，有几天、缺哪天必须写在表头。
15. **期初口径标注**。合同期从月中开始，不写「上月最后一天」，写「本期铺货（无上期结转）」。
16. **贴花只列示、不替用户决定兑付方式**。抵扣货款还是单独支付，写进口径说明由双方确认。
17. **不编造促销物料使用量**。乙方未提供使用数据时，只能按「已出库即计列（注明未经确认）」或「只列示不认定」两种口径出数；不得按经验比例、历史均值或任何无来源的数字填充，也不得计入结算金额。

18. **不替用户定口径**。任何业务口径未逐项确认前，不得出账、不得补表、不得生成任何 .xlsx；禁止用规程默认值静默填充。
19. **口径必有记录**。每次出账 / 补表必须有当期 `_口径确认.json`（含确认人、时间、全部必填 decisions 与 `internal_only`）；只写在对话或脚本注释里不算数。
20. **内部规则绝不上纸面**。`internal_only` 内容不得以任何载体进入单据（单元格、批注、页眉页脚、文档属性、表名）；使用量等内部出数规则**只出数字**。
21. **口径变更须重走门禁**。改结存依据 / 分档 / 基准日 / 表号 / 模块开关 / 使用量规则，必须重发问卡、重新确认、重新出账、重做 L6；禁止就地改 JSON 后直接重跑。
22. **增量补表不碰旧表**。`frozen_sheets` 一个字不改，`00` 只加说明，重做的表整张重建；任何越界即阻断。
23. **效期能力不得删除**。某期不做效期只能用 `expiry.enabled=false`，不得删代码、删文档或删演示夹具；关闭时 00 表三处引用同步裁剪。

## 8. 已知坑

1. **品名变体**：括号全半角、空格、`（限定版）`后缀两侧写法不同。一律以**商品条码**为匹配键；甲方挂账表无条码时先归一化（去空格、括号统一、去后缀）再映射，并在 `03` 表列「品名差异说明」。
2. **零库存 SKU**：新品以 0 数量挂在 ERP 表，会稀释「相符 SKU」计数。区分「有铺货 / 零库存」并注明。
3. **同流水号多行**：同一单号下同 SKU 拆行正常。判重键用「流水号 + 条码 + 数量」，且必须用库存倒推验证合计。
4. **库存混入非结算品**：陈列装、单片装常不在甲方挂账表内。单独成块，标「甲方挂账表未列示」，不并入结算口径。
5. **调价 / 调贴花**：价格表、贴花表都带生效起止；调整时旧行补止日、新行起新生效日，两行并存；不可回溯改历史值。
6. **合同逐字句 vs 规范值**：抽取的「结算方式」是整句，主档要「铺货代销」这类短值。抽取脚本已做规范化，原句留在 evidence。
7. **合同多版本**：同一客户可能有合同归档版与执行版（门店数不同）。以执行版为业务依据，但在摘要中注明差异。
8. **政策表条码不可全信**：附件里出现过条码抄错（两个 SKU 同码）与漏填条码的行。录主档时按品名对齐并在备注注明源表问题，不照抄。

9. **AI 自行推定业务口径**：把「效期表数量」当结存、把内部出数规则印上纸面、按 30/90/180 天分档——本轮全部发生过。统一由阶段 G 问卡阻断。
10. **表号反复交换、交叉引用错配**：删了 sheet 却留着 00 表引用。由 `sheet_map` + `verify_refs` 事前阻断。
11. **一次性脚本注释当口径记录**：下期读不到。口径必须落 `_口径确认.json` 并归档 `_确认记录/`。
12. **文档属性被 openpyxl 回填**：`creator` / `lastModifiedBy` 需在最后一次保存后用 zip 级补丁清除，`check_public_copy.py` 会断言。

## 9. 复核模式

复核分两种，共用 [references/复核协议.md](references/复核协议.md) 的 R1–R10 清单与报告 schema：

**A. 本次出账复核（L6，交付前必过）**

1. 生成复核包：`python3 "$SKILL_DIR/scripts/make_review_packet.py" "<工作簿.xlsx>" --master "<_主档.xlsx>" --out /tmp/复核包.json --md /tmp/复核包.md`（含哈希、figures、claims、cross_refs、redline_scan 等结构化底稿）。
2. 由**当前 harness 的 LLM** 按 [references/复核协议.md](references/复核协议.md) 逐项复核并写出报告 JSON（schema `dealer-settlement/review-report@1`；脚本不调用外部模型）。
3. 落盘：`python3 "$SKILL_DIR/scripts/apply_review.py" "<工作簿.xlsx>" "<报告.json>" --packet /tmp/复核包.json --apply` → 写 `08-复核记录` + `_复核记录/复核锁.json`；交付前 `--check` 必须返回「复核有效」。
4. 不通过 / 有阻断 → 不得交付；修正后重新出账、重新生成复核包并**重做 L6**（任何保存都会使复核锁失效）。

**B. 外部工作簿复核（无复核包时，按清单直查）**

1. 用 `openpyxl` 读全部单元格与合并区，读公式而非缓存值（`data_only=False`）。
2. 按 [references/复核协议.md](references/复核协议.md) 的 R1–R10 逐项核：逐表合计 = 明细之和（差异类按**绝对值**比对，正负号看行内符号）、跨表同一指标一致、恒等式逐式成立、贴花独立复算、①–⑦ 结转、交叉引用真实存在、文字断言与数据匹配、口径披露完整、红线、合同条款、差异解释。
3. 只报**实算能证明**的问题，给单元格地址与两个具体数字对比；输出同 schema 的报告 JSON 便于留档（无写权限时交给用户归档）。

## 10. 故障与回滚

高频报错速查（完整对照见 [references/故障与回滚.md](references/故障与回滚.md)）：

| 报错 | 含义 | 处理 |
|---|---|---|
| `[中止] 本次对账缺少必要信息…` | 没先跑 load_master，或主档 / 源文件 / `master_path` 缺失 | 按报错里的整行命令修复后重跑；**不要**试图绕过 |
| `[中止] RECON_CFG 不是合法的配置 JSON…` | 配置被截断或手工改坏 | 重跑 load_master 生成整行配置 |
| `[找不到主档]` / `[无法读取主档]` | 主档路径错、非 .xlsx 或已损坏 | 核对路径；.xls 先另存为 .xlsx；或用 make_master.py 建模板 |
| `[缺少源文件] …` / `[目录不存在]` | 文件名不含关键词、放错期间目录，或 `--base` 目录不存在 | 对照第 1.2 节命名约定改名 / 移动，或 `--base` 指定 |
| `[中止] 客户根目录下有挂账文件…` | 根目录有导出但无可识别月份子目录 | 放进对应月份目录，或 `--base` 指定 |
| `[参数错误] --period / --asof / --pay …` | 期间非 6 位年月，或日期不是 YYYY-MM-DD | 改成 `202610` / `2026-11-02` 形式 |
| `[中止] 含关键词 … 的工作表有 N 张…` | 源文件里多张表名都匹配，脚本不猜 | 只保留一张或改表名（唯一含数据表时会以 ⚠ 提示后采用） |
| `[自检未通过] …`（结算属性未明确、贴花缺记录、数量恒等式不成立等） | L3 / L4 校验拦截 | 按提示补主档 / 修源表；缺失值不会被默认 |
| `拒绝 …须为数字/日期/枚举…` | 确认单脏值被 L2 拦截 | 请用户在确认页修正后重新提交，再跑 A3.5 自动定位最新确认单 |
| `[未找到确认单]` | 用户还没点「提交」、浏览器下载位置未知，或换了浏览器 / 电脑 | 一句话问用户（是否已点「提交」？是否换了浏览器 / 电脑？）；必要时 `--dir "<下载目录>"` 兜底，**不要让用户搬文件** |
| `[确认单有多个候选]` | 下载目录附近有多份近期确认单 | 助手用最新一份并明确说「用了最新提交的那份」，或一句话请用户确认 |
| `[中止] 确认单缺少确认人（meta.operator 为空）` | 确认页未填确认人 | 请用户在确认页填姓名后重新提交，再跑 A3.5 自动定位 |
| `[保护] 目标文件已存在…` + stdout `[覆盖→<新文件名>]` | 防覆盖，属正常保护 | 确认后改名，或在配置加 `"overwrite": true` |
| `[写入失败]`（`apply_contract.py` 会附 `_备份/` 位置） | 目标被 Excel 占用、磁盘或权限问题 | 关闭 Excel / WPS 后重试；按提示从 `_备份/` 取快照 |
| `--check` 报「复核无效 / 复核锁缺失 / 哈希不一致」 | 工作簿复核后又被保存，或未做 L6 | 不得交付；重新生成复核包 → 重做 L6 → `--apply` |
| 复核报告校验失败（checklist 未覆盖 R1–R10、阻断与结论不一致、有警告却判「通过」、摘要为空） | 报告不合规 | 按报错修正报告后重试（规则见 [references/复核协议.md](references/复核协议.md)） |
| `_数据映射.json` 损坏 / 映射指向不存在的表或列 | 映射与当前源文件不一致 | 重跑 `inspect_schema` 生成映射，经用户确认后再 `--write` |
| `必须经用户确认`（`apply_mapping.py` 缺 `--confirmed-by`） | 违反确认门禁 | 先 dry-run 展示、用户逐项裁决，再加 `--confirmed-by "<姓名>"` |

回滚要点：主档取 `_备份/` 最近快照覆盖；对账单不覆盖同名文件（写 `_v2`）；`_确认记录/` 归档不动（审计痕迹）。详见 [references/故障与回滚.md](references/故障与回滚.md)。

### 三条硬规矩

1. **不用内置兜底路径**。引擎在无配置时直接中止（exit 1、stdout 0 字节），避免把测试结果写进客户目录。
2. **不在客户目录里做实验**。试跑用 `load_master.py ... --out /tmp/xxx.xlsx` 指定输出（`recon_engine.py` 本身无参数）。
3. **写库前必看 dry-run**。`apply_contract.py` 默认只打印差异，确认无误再加 `--write`。

## 12. 能力边界（明确不适用，避免误用）

1. 仅适用于「铺货代销 + 按实际动销结算 + 月末一次性对账」。买断、按发货 / 签收结算、含退货冲减、返利 / 折让计价，恒等式不成立，不出数。
2. 仅支持单客户单期间、账期口径为「次月固定日付款」的月度对账。跨月结转、一甲方多乙方合并出账暂不支持。
3. 源数据必须是三方导出的结构化表格。无文本层扫描件不处理；乙方换 ERP 后须先更新列映射，脚本报错而非猜测。
4. 库存数是「乙方系统导出」不是实盘；差异只证明数量差，不作归因、不认定责任、不推定税率。
5. 合同抽取结果一律是候选值，须人工逐项确认后写库。
6. **LLM 复核不构成审计意见**：L6 与复核锁只是流程控制与留痕机制，不对数据真实性作法律或审计背书；交付责任仍在执行人与业务双方。
7. **映射确认不等于数据正确性背书**：`_数据映射.json` 只表示表名 / 列名 / 顺序的对应关系经用户认可；映射错误仍会产出错误结果，须靠引擎自检与 L6 复核兜底。
8. **浏览器安全限制**：确认页是网页，受浏览器沙箱约束，**不能直接写任意本地路径**。默认走「浏览器下载 + 助手用 `locate_confirm.py` 自动定位」；支持 File System Access API 的浏览器可选择直接存入客户目录；harness 无文件读写权限时，才由用户手动提供确认单位置（不要向普通用户解释文件格式）。
