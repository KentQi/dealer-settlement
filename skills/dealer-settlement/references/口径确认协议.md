# 口径确认协议（阶段 G）

> 一句话：**业务口径不是 AI 可以自己裁量的东西**。任何口径未逐项确认前，不得出账、不得补表、不得生成任何 .xlsx。

## 1. 为什么需要这道闸

v1.6.2 把确定性纪律都押在数据层与计算层，业务口径却写死在规程正文里（30/90/180 天分档、期末结存按期初减动销、`promo_basis` 二选一），并明文允许「后三项无变更即默认无」。结果是一次真实对账里，AI 连续猜错：把效期表的结存数量当结存基数、把甲方内部出数规则印到给乙方的单据上、按天分档而非按月、赠品表写成发货总量。每次都要整表重做。

阶段 G 把结构确认门禁（dry-run → 逐项裁决 → `--confirmed-by` → 归档 → 哈希锁）平移到业务口径一侧。

## 2. 触发与跳过

**必须走**：首次建档（含新客户、首次接手已有工作簿）、每月出账（每期一次，上期只作建议选项）、增量补表、换源表结构、模块开关变化（本期关效期 / 下期开）、分档或基准日或结存依据变化、用户在对话中出现纠正信号。

纠正信号包括（但不限于）：「这句话你没看懂」「这是写的什么」「不要写到纸面上」「这个规则是我定的」「这个就是实际发货量」。出现即**立即停手、丢弃当前草稿、只重发被纠正的那一项**，不解释、不辩护、不「先做出来给你看」。

**可以跳过**：同一期间 + 同一 `_口径确认.json` + 三份源 sha256 一致 + 同一目标工作簿的幂等重跑（仍校验哈希）；只读复核既有工作簿；纯问答；纯结构探查（若探查触及源表角色，自动升级为「换源表结构」）。

**「下期开效期」不允许跳过**：`expiry.enabled` 由 false 变 true 属口径变更，必须重新确认、重新出账、重做 L6。

## 3. 四场景业务语言问卡

问卡面向人，不出现字段名、脚本名、schema 术语。完整文本在 `scripts/koujing.py` 的 `CARDS`，AI 直接引用即可。

### 首次建档
1. 以后每个月算客户还欠多少货、该结多少钱，以哪张表说了算？哪张表里的数量是准的？
2. 有没有哪张表只是给我们自己看的、里面的数量不能拿来当结存？
3. 试用装、中小样、赠品要不要单独做一张表让客户签字确认数量？它们算不算钱？
4. 哪些话是我们自己内部定的规矩、绝对不能印到给客户的单子上？
5. 效期提醒这期要不要做？按还剩几个月提醒？从哪天算起？
6. 单子上第 08、09 张表分别放什么？哪几张要标红打印、导成一份 PDF 给客户盖章？
7. 挂账表上只有物料号、没有条码时，有没有一张对照表能对上？

### 每月出账
1. 这个月按哪天截止？上期剩下来的数转过来是多少？
2. 这个月发出去多少、客户实际用了多少？正装和赠品分别说。
3. 赠品使用量这次按什么数出？还按上次那个规矩吗？
4. 效期这期开不开？分档和起算日跟上次一样吗？
5. 有没有新表、新列、新物料号，或者换过导出系统？
6. 对客户的说法跟上期一样吗？有没有哪句话这次不能写？

### 增量补表
1. 这份工作簿是哪一期？哪几张表一个字都不能动？
2. 要补哪几张表、编号排第几？补完一共几张？
3. 补的表里每个数字从哪张源表、哪一列来？跟前面几张表要对得上吗？
4. 补的这张表要不要客户签字确认？哪些表要一起导成 PDF？
5. 上次定过的口径这次还作数吗？有哪条要改（比如效期这次做不做）？
6. 有没有只能我们内部知道、不能印到补的表上的规矩？

### 换源表结构
1. 这张新表是谁发的、管什么的？跟老表是不是一回事？
2. 哪一列是数量、哪一列是编码或条码？跟老表对不上时以谁为准？
3. 原来定的「哪张表说了算」还成立吗？要不要换？
4. 条码和物料号的对照还全吗？有没有新商品没登记？
5. 结构变了之后，之前定过的口径有没有哪条要跟着改？

用户答「按上次的」时，必须追问「上次哪一条，请复述一遍」，禁止自行套用。

## 4. 确认记录 `_口径确认.json`

放在**客户根目录**（与 `_数据映射.json` 同级），不写进主档六表：主档存「不该变的东西」，口径存「每期可能变的东西」。

| 层级 | 字段 | 说明 |
|---|---|---|
| 顶层 | `schema` | `dealer-settlement/koujing@1` |
| 顶层 | `customer` / `period` / `asof` / `scene` | 客户、期间、数据基准日、四场景之一 |
| 顶层 | `confirmed_by` / `confirmed_at` | **必填**，缺失即阻断 |
| 顶层 | `config_sha256` / `prev_config_sha256` | 本份哈希 / 上一份哈希（哈希链） |
| 顶层 | `internal_only[]` | 永不进单据的内容：出数规则文本、内部用途、系统名 |
| 顶层 | `disclosure_whitelist[]` | 单据唯一允许引用的表头与说明句 |
| 顶层 | `notes[]` | 每项裁决的业务语言原话留痕 |
| `decisions` | `settlement_basis` | 结存与结算唯一依据，及明确排除的来源 |
| `decisions` | `category_source` | 商品分类：正装 / 试用装 / 中小样 发货量 |
| `decisions` | `promo` | 是否结算、是否单独出表、是否需乙方签认、`policy_note`（经确认的对外说明片段，可空，**每期确认不继承**） |
| `decisions` | `rolling` | 期初来源、是否结转、首期期初 |
| `decisions` | `usage` | `values`（汇总）、`ledger`（逐项既成数字）、`source`、`private` |
| `decisions` | `expiry` | `enabled`、`tiers`、`unit`、`base`、`fifo`、`sample_qty_basis` |
| `decisions` | `barcode_bridge` | 条码 ↔ 物料编码对照是否需要 |
| `decisions` | `sheet_map` | `08` = 试用装与中小样，`09` = 效期预警 |
| `decisions` | `print` | `red_sheets` / `pdf_sheets` |
| `decisions` | `delta` | `mode` / `frozen_sheets` / `note_only_sheets` / `rebuild_sheets` |

`usage.ledger` 每行：`name`、`kind`（试用装 / 中小样 / 赠品 / 配赠 …，类型不固定）、`link`（对应正装，可选）、`sales`（正装销量，可选）、`opening`、`shipped`、`used`。`closing` 由脚本按 `opening + shipped − used` 计算，**不写入规则文本**。

### 使用量三态

| 态 | 录入 | 单据呈现 | 引擎行为 |
|---|---|---|---|
| 甲方口径 | 用户私下给规则，只把**结果数字**填进 ledger | 只有数字 | 不推导、不重算，逐行断言恒等式 |
| 乙方提供 | 逐物料给数 | 数字 | 同上 |
| 未提供 | `used` 留空 | 使用与期末显示「—」 | 不按 0、不按销量或经验比例推算；期末不出数 |

## 5. 阻断行为

`load_master.py` 在生成 `RECON_CFG` 之前调用 `koujing.load()`。任一项缺失、类型错误、`internal_only` 与白名单重叠、哈希不匹配、场景不匹配：

- `exit 1`，**stdout 保持 0 字节**，不生成任何文件
- stderr 输出「本次口径未确认，缺以下 N 项」+ 对应业务语言问卡原文
- 不得用规程默认值静默填充

历史期间只读复核可用 `load_master.py --allow-legacy` 显式放行（stderr 强警告，产物不得作为正式交付件）。

## 6. 留痕与防改口径

1. 确认后写 `_口径确认.json`，副本归档 `_确认记录/口径_YYYYmmdd_HHMMSS_mmm.json`（毫秒时间戳、不覆盖）。
2. `load_master.py` 把 `config_sha256` 注入 `RECON_CFG['koujing']`，引擎与 `apply_v17.py` 都读同一份。
3. 复核包与 `复核锁.json` 记录 `koujing_sha256`；`--check` 比对当前文件哈希，不一致判「复核无效：口径确认可能已变更」。
4. 改口径 → 哈希变 → 锁失效 → 必须重发问卡、生成新记录（`prev_config_sha256` 指向旧记录）、重新出账、重做 L6。**禁止就地改 JSON 后直接重跑**。
5. 每期归档 + 哈希链，形成「本期关效期 → 下期开效期」的显式变更轨迹。

## 7. 命令

```bash
# 生成待填模板（不含确认人，必然被门禁阻断，防止误用）
python3 "$SKILL_DIR/scripts/koujing.py" --base "<客户根目录>" --template \
  --scene 每月出账 --period 202610 --asof 2026-11-02

# 逐项确认后校验
python3 "$SKILL_DIR/scripts/koujing.py" --base "<客户根目录>" --scene 每月出账 --check

# 正常出账（load_master 内部自动校验）
export RECON_CFG=$(python3 "$SKILL_DIR/scripts/load_master.py" "<客户根>/_主档.xlsx" \
  --period 202610 --asof 2026-11-02 --overwrite [--pdf] [--mode incremental --in-workbook <簿>])
python3 "$SKILL_DIR/scripts/recon_engine.py"
python3 "$SKILL_DIR/scripts/apply_v17.py" --cfg /tmp/cfg.json
```
